# 第一梯队 · 闭合核心循环

> 目标：补齐「打怪 → 掉落 → 变强 → 再战 / 推进任务」的正反馈环，以及「战斗失败有代价但不软锁」的负反馈。

---

## 1. 掉落系统（Loot）

### 1.1 目标与现状

- **现状**：`EnemyBase._on_died()` 只通过 `KillXpGranter` 发经验，**敌人/宝箱不掉任何物品**。`WorldItem.spawn_at()` 已能在场景里生成可拾取物，但没有「谁掉、掉什么、掉多少」的数据层。
- **目标**：用 **Resource 掉落表** 驱动击杀掉落与宝箱开启掉落；与 `ItemDatabase` 的 `id` 对齐；新增掉落只改数据不改脚本。

### 1.2 数据结构

新增三个文件（`scripts/core/loot/`）：

**`LootEntry`（RefCounted-style Resource）** — 单条掉落项

```gdscript
class_name LootEntry extends Resource
@export var item_id: String = ""           # 对齐 ItemDatabase
@export var weight: float = 1.0            # 在所属 roll 内的相对权重
@export var min_count: int = 1
@export var max_count: int = 1
@export_range(0.0, 1.0) var chance: float = 1.0   # 该条独立命中概率（1=必出，用于保底/独立掉落）
```

**`LootTable`（Resource）** — 一张掉落表

```gdscript
class_name LootTable extends Resource
## 独立掉落：每条按自身 chance 单独判定（保底物 / 任务材料）
@export var guaranteed: Array[LootEntry] = []
## 加权抽取：先按 roll_count 决定抽几次，每次在 weighted 里按 weight 抽 1 条
@export var weighted: Array[LootEntry] = []
@export var roll_count_min: int = 1
@export var roll_count_max: int = 1
## 整张表是否触发的总开关概率（如 30% 怪才掉东西）
@export_range(0.0, 1.0) var table_chance: float = 1.0
## 金币掉落（走 world_gold_pickup，可选）
@export var gold_min: int = 0
@export var gold_max: int = 0
```

**`LootRoller`（静态工具，RefCounted）** — 纯逻辑、可单测

```gdscript
class_name LootRoller extends RefCounted
## 返回 [{item_id, count}]，纯函数，rng 可注入便于测试
static func roll(table: LootTable, rng: RandomNumberGenerator) -> Array
## 把 roll 结果在世界里生成（金币 + 物品散落），供运行时调用
static func spawn_drops(table: LootTable, parent: Node, origin: Vector2, rng: RandomNumberGenerator) -> void
```

> **为何拆 `guaranteed` / `weighted`**：保底物（任务材料、必出货币）与随机战利品语义不同，混在一个权重池里会让「必出」难以表达。这与现有 `MonsterStatProfile`/`MonsterSpawnRule` 的「规则 + 条目」分层风格一致。

### 1.3 挂载组件（组件即功能）

**`LootDropperComponent`** — 仿照 `KillXpGranter`，挂在 `EnemyBase` 子节点：

```gdscript
class_name LootDropperComponent extends Node
@export var loot_table: LootTable           # 怪物专属表
@export var use_global_fallback: bool = false  # 无表时是否用全局默认表
# _ready(): 解析同级 CombatantComponent，连接 died
# _on_died(last_hit): 仅当击杀者为玩家阵营时 LootRoller.spawn_drops(...) 落在自身位置
static func ensure_on(parent: Node) -> LootDropperComponent  # spawn 流程统一入口
```

- 摘下组件 = 该怪不掉落（符合「组件即功能」）。
- 与 `KillXpGranter` 并列，互不依赖；都监听同一个 `died` 信号。
- **宝箱**：`StorageChest` / 新的 `LootChest` 在「开启」交互里直接调 `LootRoller.spawn_drops()` 或把战利品塞进箱体库存（二选一，建议散落以复用拾取动画）。

### 1.4 数据文件布局

```
resources/loot/
  tables/
    grassland_common.tres     # 草原杂兵
    boss_chapter1.tres        # 章节 Boss
  global_fallback.tres        # 兜底表（可选）
```

掉落表通过 `MonsterStatProfile` 或 `MonsterSpawnEntry` 引用（新增一个 `@export var loot_table: LootTable` 字段），由 spawn 流程在 `LootDropperComponent.configure()` 时写入——和现有 `KillXpGranter.configure()` 完全同构。

### 1.5 存档

掉落物落地后是 `WorldItem`；玩家拾取走现有 `try_pickup_item()`。**已掉落但未拾取的战利品默认不持久化**（重进场景刷新，符合常规 ARPG）。唯一需要持久化的是 Boss/唯一怪的**一次性掉落**——复用 `_world_state.defeated_unique_enemies`：唯一怪死亡前先查该列表，已在列表则不再掉。

### 1.6 验收标准

- 给草原杂兵配 `grassland_common.tres`，击杀后稳定按权重掉落且数量在区间内。
- `LootRoller.roll()` 单测：固定 seed → 固定结果；`table_chance=0` → 空；`chance=1` 的 guaranteed 必出。
- 摘除 `LootDropperComponent` → 不掉落，无报错。

> **实现记录**：[掉落系统实现记录](systems/掉落系统实现记录.md)（含落地弹跳动画、草原测试配置与字段说明）

## 2. 死亡 / 重生系统

### 2.1 目标与现状

- **现状**：`CombatantComponent` 已发 `died`，但**玩家死亡无任何处理**（HP 归零后无重生、无结算、无失败界面），等于战斗没有失败代价。
- **目标**：玩家死亡 → 失败界面 → 重生（重生点 / 读最近存档）+ 轻惩罚；**避免软锁**（不会卡在无法继续的状态）。

### 2.2 重生点：`RespawnPoint`

```gdscript
class_name RespawnPoint extends Area2D
@export var point_id: String = ""
@export var is_default: bool = false   # 场景默认重生点
# body_entered(Player): 记录为「当前激活重生点」→ DeathManager.set_active_respawn(...)
#                       同时可触发一次自动存档（检查点语义）
```

- 重生点 id 写入 `_world_state["active_respawn"] = { scene, point_id, pos }`，跨场景持久化。
- 无任何重生点时回退到**场景默认出生点**或**读取最近存档**（双保险，防软锁）。

### 2.3 协调器：`DeathManager`（Autoload）

集中处理死亡流程，避免 `Player` 膨胀（单一职责）：

```gdscript
extends Node   # Autoload: DeathManager
signal player_died
signal player_respawned

func _ready():
    # 玩家就绪时连接其 CombatantComponent.died
func _on_player_died(last_hit):
    # 1) 暂停玩家输入 / 锁操作
    # 2) 弹出 GameOverUI（淡入）
    # 3) 等玩家选择：重生 / 读档 / 回主菜单
func respawn():
    # 1) 应用惩罚（见 2.4）
    # 2) 玩家移动到 active_respawn / 默认点，HP/MP 回满，is_alive=true
    # 3) emit player_respawned；恢复输入
```

> 复用现有 `UILayerManager` 弹层、`SaveManager.load_game()` 读档、暂停菜单的输入锁范式。

### 2.4 惩罚（数据驱动，`DeathPenaltyConfig` Resource）

```gdscript
class_name DeathPenaltyConfig extends Resource
@export_range(0.0, 1.0) var gold_loss_ratio: float = 0.1   # 掉落部分金币
@export var drop_gold_in_world: bool = false                # 金币是否散落在死亡点可捡回（魂类）
@export var respawn_hp_ratio: float = 1.0                   # 重生 HP 比例
@export var durability_loss: int = 0                        # 装备耐久惩罚（对接现有耐久）
```

默认温和（仅扣 10% 金币、满血复活）。策划可在 `resources/config/death_penalty.tres` 调档，不改脚本。

### 2.5 失败界面：`GameOverUI`

- 选项：**重生**（回激活重生点）/ **读取存档** / **返回主菜单**。
- 走 `UILayerManager`，`process_mode = ALWAYS`（树暂停时仍可交互）。

### 2.6 存档

`_world_state` 新增 `active_respawn`（`export_world_state` / `import_world_state` 已统一序列化 `_world_state`，加字段即可）。

### 2.7 验收标准

- 玩家 HP 归零 → 失败界面出现、操作锁定、无脚本报错。
- 选「重生」→ 回到最近触碰的重生点、满血、可继续战斗。
- 无重生点的场景死亡 → 回退默认点或读档，**不软锁**。
- 扣金币比例与配置一致。

> **实现记录**：[死亡重生系统实现记录](systems/死亡重生系统实现记录.md)

## 3. 任务目标类型扩展

### 3.1 目标与现状

- **现状**：`ObjectiveType` 枚举已列 5 种，但 `QuestManager` 只实装了 `KILL_ENEMY`（`notify_enemy_killed`），其余是预留位。剧情只能靠「杀 N 个怪」推进。
- **目标**：实装 `COLLECT_ITEM` / `TALK_TO_NPC` / `ENTER_AREA`，让任务能表达「收集 / 对话 / 抵达」——这是剧情推进的最小必需集。改动小、回报大。

### 3.2 各目标类型的推进入口（全部走现有 `advance_objective` 范式）

`QuestManager` 已有通用入口 `advance_objective(quest_id, objective_id, amount)` 与逐类型分发结构。新增三个「监听 → 匹配 → 推进」方法，与 `notify_enemy_killed` 同构：

**COLLECT_ITEM** — 监听背包变化（拥有量达标即完成，可逆）

```gdscript
# QuestManager 连接 Inventory/Player 的 inventory_changed 信号
func notify_inventory_changed(item_id, owned_count):
    # 遍历活跃任务 COLLECT_ITEM 目标，target_id == item_id 时
    # 把 progress 直接设为 min(owned_count, required)（不是 +1，按持有量重算）
```

> 关键差异：收集类按**当前持有量**重算而非累加，避免「丢弃后仍算完成」。需要 `QuestInstance` 增加 `set_progress(objective_id, value)`。

**TALK_TO_NPC** — NPC 交互时调用

```gdscript
func notify_npc_talked(npc_id):
    # 匹配 TALK_TO_NPC 且 target_id == npc_id 的目标，advance 1
```

接入点：现有 NPC 交互（`quest_giver_npc` / `cutscene_npc` / `merchant_npc`）在交互回调里加一行 `QuestManager.notify_npc_talked(npc_id)`。

**ENTER_AREA** — 区域触发器

```gdscript
class_name QuestAreaTrigger extends Area2D
@export var area_id: String = ""
# body_entered(Player): QuestManager.notify_area_entered(area_id)
```

```gdscript
func notify_area_entered(area_id):
    # 匹配 ENTER_AREA 且 target_id == area_id 的目标，advance 1
```

### 3.3 数据结构影响

- `QuestObjectiveDef` 已有 `objective_type` / `target_id` / `required_count`，**字段够用**，无需扩展。
- `QuestInstance` 需补 `set_progress()`（供 COLLECT_ITEM 按持有量重算）。
- 存档：`export_quest_state` 已序列化 `progress` 字典，新类型自动覆盖，无需改存档格式。

### 3.4 验收标准

- 「收集 3 个草药」：捡到第 3 个完成；丢弃 1 个回退为 2/3（未交付时）。
- 「与老兵对话」：交互一次完成。
- 「抵达村口」：走进触发区完成。
- 三类目标进度都能存档 / 读档后保持。

## 4. 任务追踪 UI + 极简地图 / 导航

### 4.2 设计

**`QuestTrackerUI`**（挂 `game_hud.tscn`）

- 维护「当前追踪任务」（默认最近接取；可在 Journal 里切换）。

## 5. 音频系统

### 5.1 目标与现状

- **现状**：整个 `scripts/` 无任何 `AudioStreamPlayer`（仅 Dialogic 插件自带）。无 BGM、无打击音效、无 UI 音效——明显的体验断层。
- **目标**：一个轻量 `AudioManager`（Autoload）：BGM 分轨切换 + SFX 池 + 与设置联动的音量分级。

### 5.2 设计

**`AudioManager`（Autoload）**

```gdscript
extends Node
# 总线：Master / Music / SFX / UI（在 Audio Bus Layout 里建好）
func play_music(stream: AudioStream, fade: float = 0.5)   # 交叉淡入，避免硬切
func stop_music(fade: float = 0.5)
func play_sfx(stream: AudioStream, pos: Vector2 = INF)    # 2D 定位可选
func play_ui(stream: AudioStream)
func set_bus_volume_db(bus: String, db: float)            # 设置面板调用
```

- **SFX 池**：预创建 N 个 `AudioStreamPlayer2D` 轮转复用，设并发上限防卡顿（路线图 P3-2 的「音效池」）。
- **BGM 分层**：探索 / 战斗 / 城镇三种状态，由场景或战斗状态触发 `play_music()` 交叉淡入。

### 5.3 数据驱动接入

- 武器命中、法术施放、拾取、升级、UI 点击等**已有信号**处挂音效，音效资源用 `@export var hit_sfx: AudioStream` 配在对应 Resource（武器/法术）上，**不在脚本里写死路径**。
- BGM 列表配 `resources/audio/` + 一个 `MusicTrackSet` Resource（场景 → 曲目映射）。

### 5.4 验收标准

- 进入战斗场景 BGM 自动播放并可交叉切换。
- 攻击命中 / 拾取 / 升级有音效，无明显爆音或卡顿。
- 设置面板调音量即时生效并存档。

## 7. 场景过渡

### 7.1 目标

### 7.2 设计

**`SceneTransition`（Autoload + 全屏 `CanvasLayer` 遮罩）**

```gdscript
func change_scene(path: String) -> void:
    # 1) 淡出（黑/自定义遮罩）
    # 2) get_tree().change_scene_to_file(path)（或预载 PackedScene 异步）
```

- 配合 §2 重生、传送点统一走这里，保证「黑屏瞬间」做位置/数据切换。

### 7.3 验收标准

- 场景切换有淡入淡出，无突兀黑屏跳变。

## 8. 世界旗帜系统

- **现状**：`SaveManager._world_state` 已存 `picked_up_items / gathering_spots / merchants / defeated_unique_enemies / storage_chests`，但**没有通用布尔 / 枚举旗帜**供对话与任务查询。
- **设计**：在 `_world_state` 增 `flags: Dictionary`，封装 `SaveManager.set_flag(key, value)` / `get_flag(key, default)` / `has_flag(key)`。门、NPC 阶段、商店解锁、剧情节点统一用它。`export/import_world_state` 已序列化 `_world_state`，加字段零成本。
- **接入**：Dialogic 条件分支、`QuestManager` 前置条件、`InteractableObject` 开关查询该旗帜。
- **验收**：设置旗帜 → 存档读档后保持；对话 / 任务能按旗帜走不同分支。

## 9. 修理 / 强化 / 合成（先做修理）

- **现状**：物品耐久字段（`max_durability`）已存在、采集工具会磨损，但**没有修理 / 强化 / 合成闭环**。
- **设计（先修理站）**：
  - `RepairStationUI`：选背包内有耐久的物品 → 按 `缺失耐久 × 单位修理价（与 value_gold 挂钩）` 扣金币回满。复用 `TradeSettlement` 的结算范式。
  - 强化 / 合成列为后续：用 `RecipeResource`（输入物品 id + 数量 → 输出 + 金币）驱动，数据层即可扩展。
- **验收**：修理扣费正确、耐久回满、金币不足时拒绝并提示。

## 10. 敌人 AI 多样化与攻击预警（telegraph）/ Boss

- **现状**：敌人行为偏单一（追击 + 扇形视野巡逻）。
- **设计**：
  - **攻击预警**：攻击前摇期间显示地面预警标记（复用 `spell_ground_marker` 范式），给玩家反应窗口。
  - **行为多样化**：基于现有 `ChaseBehaviorResource` 体系扩展「保持距离风筝」「冲锋」「召唤」等行为资源。
  - **Boss**：多阶段（按 HP 比例切行为）+ 专属掉落表（接 §1）+ 唯一击杀持久化（`defeated_unique_enemies`）。
- **验收**：Boss 能按阶段切换行为，攻击有预警，击杀掉专属战利品且只掉一次。
