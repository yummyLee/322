# 文档目录索引

本目录下按"主题"分子目录归档。新写文档时请按下表选择归档位置；写完后把链接添加到对应章节。

| 子目录 | 归档内容 | 主要读者 |
|---|---|---|
| [`conventions/`](#conventions) | 跨模块的约定、命名规范、流程性文档 | 所有 Agent 和开发者 |
| [`systems/`](#systems) | 各个核心子系统（战斗/Buff/法术/物品/UI...）的总体设计 | 维护该系统或做跨系统改动时 |
| [`spells/`](#spells) | 单个法术/单个 Buff 的实现记录 | 新增类似法术或调该法术参数时 |
| [`scenes/`](#scenes) | 关卡/场景配置说明 | 改场景、改怪物分布、改出生点时 |
| [`narrative/`](#narrative) | 世界观、剧情、角色背景、属性公式草案 | 做剧情 / 写角色文案 / 查属性公式 |
| [`planning/`](#planning) | 策划草案、待实现的点子 | 规划新功能时作为备选 |

## 写文档的注意事项

1. **归档位置**：按上表选子目录。拿不定主意就先写到对应 `systems/`。
2. **命名**：中文名即可，沿用现有风格（如 `xxx设计记录.md` / `xxx系统.md`）。
3. **交叉引用用相对路径**：同目录 `./x.md`，跨目录 `../子目录/x.md`，**不要**再写 `docs/x.md`。
4. **代码里引文档**：用完整仓库路径 `docs/子目录/x.md`（不要 `res://docs/...`，docs 不随游戏打包）。
5. **一条实现落地 → 一份实现记录**：大系统（Buff/法术/武器）的增量特性单独开 `xxx实现记录.md`，挂到对应 `systems/` 里；如果是一个完整的新法术，放 `spells/`。
6. **和代码对齐**：设计文档和代码不一致时，以代码为准并修文档；`systems/Buff系统设计记录.md` / `planning/技能设计.md` / `systems/法术系统设计记录.md` 文档头有"实现进度速查"表，新增功能时同步更新。
