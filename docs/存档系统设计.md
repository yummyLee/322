# 存档系统设计文档

## 1. 概述

为 openworldtest 项目实现完整的存档/读档/新游戏功能。参考《塞尔达传说：旷野之息》《黑暗之魂》《星露谷物语》等游戏的存档设计，采用多槽位 + 自动存档的方案。

### 设计目标
- **完备性**：覆盖所有需要持久化的游戏状态
- **健壮性**：版本兼容、损坏检测、加载回退
- **易用性**：多槽位、自动存档、清晰的 UI 反馈
- **可扩展**：新增游戏系统时容易追加存档字段

---

## 2. 存档架构

### 2.1 文件结构

```
user://saves/
├── slot_0/
│   ├── save.json          # 主存档数据
│   ├── meta.json           # 槽位元数据（列表显示用）
│   └── thumbnail.png       # 截图缩略图
├── slot_1/
│   └── ...
├── slot_2/
│   └── ...
└── slot_autosave/
    └── ...
```

- **3 个手动存档槽** + **1 个自动存档槽** = 共 4 个槽位
- 每个槽位独立目录，便于管理和删除
- `meta.json` 在未加载完整存档时就能快速展示槽位信息

### 2.2 存档流程

```
保存: 游戏运行态 → SaveDataBuilder(收集各系统快照) → JSON序列化 → 写入磁盘
加载: 读取磁盘 → JSON反序列化 → SaveDataApplier(分发到各系统) → 重建游戏运行态
新游戏: 使用项目默认值初始化所有系统 → 进入初始场景
```

### 2.3 版本策略

存档文件包含 `version` 字段（semver 格式）。加载时：
- 主版本号不同 → 拒绝加载（不兼容）
- 次版本号不同 → 尝试迁移（调用迁移函数）
- 补丁版本号不同 → 直接加载（兼容）

## 3. 需要保存的数据 - 完整清单

### 3.1 玩家数据

| 分类 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 基础 | `current_scene` | String | 当前场景路径（如 `res://scenes/world/mountain1_scene.tscn`） |
| 基础 | `global_position_x` | float | 玩家世界坐标 X |
| 基础 | `global_position_y` | float | 玩家世界坐标 Y |
| 基础 | `gold` | int | 金币数量 |
| 背包 | `inventory` | Array[SlotData] | 10 格背包：每格 {item_id, quantity, durability?} |
| 装备 | `equipment` | Dict[int→SlotData] | 6 槽位：槽位类型枚举 → {item_id, durability?} |
| 属性 | `current_hp` | float | 当前生命值 |
| 属性 | `current_mp` | float | 当前法力值 |
| 属性 | `base_str` | float | 基础力量 |
| 属性 | `base_agi` | float | 基础敏捷 |
| 属性 | `base_int` | float | 基础智力 |
| 属性 | `base_con` | float | 基础体质 |
| 属性 | `base_luk` | float | 基础幸运 |
| Buff | `buffs` | Array[BuffData] | 玩家身上的活跃 Buff 列表 |
| 等级 | `level` | int | 玩家等级 (1-99) |
| 等级 | `experience` | int | 当前等级段经验值 |
| 技能栏 | `spell_hotbar` | Array[{keycode, spell_id}] | 8 个快捷键绑定 |
| 技能CD | `spell_cooldowns` | Dict[spell_id→remaining_sec] | 各法术剩余冷却时间（秒） |

#### SlotData 结构
```json
{
  "item_id": "stone",
  "quantity": 5,
  "durability": 100    // 仅当 item.max_durability > 0 时存在
}
```

#### BuffData 结构
```json
{
  "def_id": "slow",
  "remaining": 3.5,        // -1.0 表示永久
  "stacks": 2,
  "source_tag": "spell:frost_trail",
  "source_skill_id": "frost_trail",
  "tick_accumulator": 0.3
}
```

### 3.2 世界状态

#### 3.2.1 场景掉落物（WorldItem）

WorldItem 是场景中放置的可拾取物品节点（如地上的石头、木材）。拾取后 `queue_free()`，需要记录已拾取的物品。

```
scene_pickups: Dict[scene_path → Array[picked_item_instance_id]]
```

**实现方式**：给每个 WorldItem 分配一个唯一 instance_id（在场景中由编辑器预设或在 `_ready` 时根据路径+名称生成），拾取后记录该 id。加载场景时，遍历所有 WorldItem，标记在已拾取列表中的进行 `queue_free()`。

替代方案（更简单）：WorldItem 在场景加载后，检查一个全局"已拾取集合"来决定是否自毁。

#### 3.2.2 采集点（GatheringSpot）

GatheringSpot 有 `_respawning` 状态和重生计时器。

```
scene_gathering_spots: Dict[spot_unique_id → {consumed: bool, respawn_remaining: float}]
```

`spot_unique_id` = `scene_path + "/" + spot_name`（场景内唯一节点名）。

- `consumed=true, respawn_remaining=0`：已采集，等待重生计时器
- `consumed=true, respawn_remaining>0`：正在重生倒计时中
- `consumed=false`：可用状态

#### 3.2.3 商人（MerchantNpc）

```
scene_merchants: Dict[merchant_unique_id → {
  inventory: Array[SlotData],     // 当前货架空位
  gold: int,
  player_sale_slots: Array[int]   // 玩家卖给商人的货架索引
}]
```

注意：商人的 `stock_refresh_timer` 剩余时间不需要保存——加载后重新开始计时即可（从定义中读取间隔）。

#### 3.2.4 敌人状态

动态生成的敌人在重新进入场景时会由 MonsterSpawner 重新生成，因此**不需要保存每个敌人的状态**。但以下情况需要关注：

- **Boss 敌人**：如果后续有独立命名的 Boss，需要保存击杀状态
- **Spawner 状态**：如果 spawner 有波次/冷却逻辑，需要保存
- **已杀死的独特敌人**：以 Dict[enemy_instance_id → bool] 记录

```
defeated_unique_enemies: Array[String]  // 已击败的独特敌人 ID 列表
```

### 3.3 任务系统

```
quests: {
  active: [{
    quest_id: "forest_grassland_hunt",
    state: 1,                              // QuestState 枚举值
    progress: {"kill_forest_monsters": 12, "kill_archers": 5}
  }],
  completed: ["side_quest_01", "side_quest_02"]  // 已交付的任务 ID 列表
}
```

QuestManager 的数据结构简洁，直接序列化其内部字典即可。

### 3.4 过场动画

```
played_cutscenes: Array[String]   // 已播放过的过场动画 ID 列表
```

防止重复播放已看过的过场。CutsceneManager 需要增加此记录。

### 3.5 全局/元数据

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | String | 存档格式版本号，如 "1.0.0" |
| `game_version` | String | 游戏版本号（用于兼容检查） |
| `play_time_seconds` | float | 累计游玩时间 |
| `save_timestamp` | int | 保存时的 Unix 时间戳 |
| `save_slot_name` | String | 槽位显示名称 |

### 3.6 当前不保存的数据（设计决策）

| 数据 | 原因 |
|------|------|
| 天气/时间系统 | 尚未实现 |
| 动态敌人位置 | 由 Spawner 重新生成，非持久化敌人 |
| UI 面板开关状态 | 加载后默认关闭，用户重开 |
| 战斗中的临时飞行弹道 | 瞬态数据，不持久化 |
| 物理速度/加速度 | 加载后自动归零，不保存运动中间态 |
| Dialogic 内部状态 | Dialogic 有自带存档机制，按需对接 |

## 4. 数据流设计

### 4.1 核心类

```
SaveManager (Autoload 单例)
├── save_game(slot: int) -> Error
├── load_game(slot: int) -> Error
├── delete_save(slot: int) -> Error
├── new_game() -> void
├── get_slot_meta(slot: int) -> Dictionary
├── get_all_slots() -> Array[Dictionary]
├── has_save(slot: int) -> bool
└── signals: save_completed, load_completed, save_failed
```

### 4.2 保存流程（save_game）

```
1. SaveManager.save_game(slot)
2. 检查当前场景是否可保存（不在过场/战斗中？视设计而定）
3. 构建 SaveData 字典：
   a. _capture_player_data()      → 从 Player + PlayerRuntimeState 抓取
   b. _capture_world_data()       → 遍历场景树收集 WorldItem/GatheringSpot/MerchantNpc
   c. _capture_quest_data()       → 从 QuestManager 抓取
   d. _capture_cutscene_data()    → 从 CutsceneManager 抓取
   e. _capture_spell_cooldowns()  → 从 SpellSystem 抓取
   f. _capture_meta_data()        → 版本号/时间戳/游玩时间
4. JSON.stringify(save_data)
5. 写入 user://saves/slot_{n}/save.json
6. 写入 meta.json
7. 截取当前画面保存为 thumbnail.png
8. 发出 save_completed 信号
```

### 4.3 加载流程（load_game）

```
1. SaveManager.load_game(slot)
2. 读取 save.json，JSON.parse
3. 版本检查 → 不兼容则报错
4. 清空当前运行时状态：
   a. QuestManager 清空活跃/已完成列表
   b. SpellSystem 清空所有冷却
   c. CutsceneManager 清空已播放列表
5. 切换到存档中的场景（change_scene_to_file）
6. 场景加载完成后（await signal）：
   a. _apply_player_data()        → PlayerRuntimeState 注入数据
   b. _apply_world_data()         → 场景中的 WorldItem/GatheringSpot/MerchantNpc 恢复状态
   c. _apply_quest_data()         → QuestManager 重建
   d. _apply_cutscene_data()      → CutsceneManager 恢复
   e. _apply_spell_cooldowns()    → SpellSystem 恢复
7. 发出 load_completed 信号
```

### 4.4 新游戏流程（new_game）

```
1. SaveManager.new_game()
2. 清空所有 RuntimeState / 管理器状态
3. 切换到初始场景（main.tscn 或第一章场景）
4. 场景加载后，Player 使用默认初始值（等级1、空背包等）
```

## 5. 关键实现细节

### 5.1 世界状态持久化 - 唯一 ID 方案

WorldItem / GatheringSpot / MerchantNpc 需要在场景中有稳定唯一 ID：

**方案A（推荐）**：给每个需要持久化的世界对象在场景中设置唯一的 `persist_id`（编辑器 `@export` 字符串）。设计师在编辑器中手动命名，如 `"mountain1_ore_01"`。

**方案B（自动）**：使用节点的场景路径（`owner.name + "/" + name`）。缺点是重命名会丢失存档兼容性。

**选用方案A**，对现有场景改动最小。给 WorldItem、GatheringSpot、MerchantNpc 各增加一个 `@export var persist_id: String = ""`，为空时不参与持久化。

### 5.2 PlayerRuntimeState 扩展

现有 `PlayerRuntimeState` 已经处理了场景切换间的玩家数据传递。SaveManager 的序列化逻辑可以完全复用 PlayerRuntimeState 中已有的序列化/反序列化代码，避免重复：

- `_serialize_inventory()` / `_deserialize_inventory()`
- `_serialize_equipment()` / `_deserialize_equipment()`
- `_serialize_combat_state()` / `_deserialize_combat_state()`
- `_serialize_progression()` / `_deserialize_progression()`
- `_serialize_hotbar_state()` / `_deserialize_hotbar_state()`
- `_serialize_buffs()` / `_restore_buffs()`

这些方法目前是 PlayerRuntimeState 的私有方法。重构为：
- 提取到 `SaveDataBuilder` 类（静态工具方法）或保留在 PlayerRuntimeState 中但改为 public
- SaveManager 调用它们来构建/恢复玩家数据

### 5.3 场景加载时序

加载存档的核心难点是**时序**：必须先切换到目标场景，等场景加载完毕（所有 `_ready()` 调用完成），再恢复世界状态。

```gdscript
# 加载场景并等待就绪
get_tree().change_scene_to_file(save_data.current_scene)
await get_tree().create_timer(0.1).timeout  # 等一帧确保 _ready 执行完
# 也可以用 await get_tree().process_frame 等待

# 此时场景节点已就绪，开始恢复
_apply_player_data(save_data.player)
_apply_world_data(save_data.world)
```

更好的做法：在场景根节点加一个 `scene_ready` 信号，场景 `_ready()` 末尾发出。SaveManager 监听该信号后再恢复数据。

### 5.4 自动存档触发时机

| 触发条件 | 说明 |
|----------|------|
| 场景切换时 | `change_scene_to_file` 调用前 |
| 任务进度更新时 | 完成一个任务目标后 |
| Boss 战前 | 进入 Boss 区域时 |
| 定时自动存档 | 每 N 分钟（可配置，默认关闭） |
| 手动存档 | 玩家在菜单中点击"保存" |

### 5.5 错误处理

```
- 存档文件不存在 → 提示"空槽位"
- JSON 解析失败 → 提示"存档损坏"，标记为损坏状态
- 版本不兼容 → 提示"存档来自较新版本的游戏"
- 磁盘空间不足 → 保存失败，提示用户清理空间
- 场景文件不存在 → 提示"存档引用的场景已缺失"
- 物品 ID 在数据库中找不到 → 跳过该物品，记录警告日志（不阻断加载）
```

## 6. UI 设计概要

### 6.1 标题画面
- **继续游戏** → 加载最近一次存档（手动或自动）
- **新游戏** → 开始新游戏
- **加载存档** → 打开存档选择列表

### 6.2 存档选择画面
- 显示 3 个手动槽位 + 1 个自动存档槽位
- 每个槽位显示：槽位名称、玩家等级、游戏时间、保存时间、所在场景名、缩略图
- 空槽位显示"空"
- 点击槽位 → 加载

### 6.3 游戏内菜单（ESC）
- **继续** → 关闭菜单
- **保存游戏** → 打开存档槽位选择（仅显示手动槽位）
- **加载游戏** → 打开存档槽位选择（确认对话框防误触）
- **返回标题** → 回到标题画面（提示保存）
