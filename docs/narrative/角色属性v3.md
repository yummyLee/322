# 角色属性系统设计 v3（重构稿）

> v3 在 v2 基础上做**结构性简化与加点系统升级**。  
> 核心目标：消除主属性之间的派生交叉、提升加点决策的差异性、改善高等级加点的"加点感"。

---

## 〇、和 v2 的差异速览

| 维度 | v2 现状 | v3 目标 |
|---|---|---|
| 主属性数量 | 5（STR/AGI/INT/CON/LUK） | **5（不变）** |
| 派生属性公式 | 多个派生由 2 个主属性共同驱动（主+次） | **每个派生只由 1 个主属性驱动**（纯净化） |
| 主属性影响面 | 4/4/6/5/4（平均 4.6 个派生） | **2/3/4/3/3**（平均 3 个派生，更聚焦） |
| 等级固定成长 | 每级每项 +1（5 维共 +5） | **取消固定成长**，把名额并入自由分配 |
| 自由点 / 级 | 3 | **5** |
| 后期加点边际 | 1 点 STR = 固定 1.5 物攻（与 1 级一样） | **等级倍率**：99 级 1 点 STR ≈ 5.18 物攻（绝对值放大 3.5×） |
| 装备词条作用 | 与主属性并列，词条可独立堆 | **不变**，但成为"扩大主属性收益"的主要手段 |

---

## 一、核心问题诊断（v2 实战中暴露）

### 1. 派生属性"主+次"导致加点雷同

v2 矩阵里多个派生由 2 个主属性驱动：

| 派生 | v2 驱动 |
|---|---|
| 物理攻击力 | STR 主 + AGI 次 |
| 暴击率 | LUK 主 + AGI 次 |
| 暴击伤害 | LUK 主 + STR 次 |
| 生命上限 | CON 主 + STR 次 |
| 护甲 | CON 主 + STR 次 |
| 魔抗 | CON 主 + INT 次 |

**后果**：

- 堆 STR 一项就能拿到：物攻 + 生命 + 暴伤 + 护甲 = **进攻 + 生存 + 暴击爆发**一条龙
- 堆 AGI 一项就能拿到：物攻次 + 攻速 + 暴击率次 + 闪避 = 也是**进攻 + 生存**一条龙
- 玩家把"主力量战士"和"主敏捷刺客"建出来，面板对比之下**只是数字大小不同，没有结构差异**
- 设计意图的"协同感"被实际玩感解读为"反正堆哪个都不亏"

### 2. 等级固定成长稀释自由加点

当前规则：

- `PRIMARY_INITIAL = 10`，`PRIMARY_FIXED_PER_LEVEL = 1`，`FREE_POINTS_PER_LEVEL = 3`
- 99 级时每维**固定** 108、**自由**最多 294，自由点仅占 **37.5%**
- 也就是说，无论玩家怎么加点，"五维基本都有 108"
- 玩家自己的策略空间只有总量的 1/3 出头

### 3. 后期加点没有"打击感"

派生公式是纯线性 `derived = stat × coef`：

- 1 级 STR=10 → 物攻 15；加 1 点 STR 物攻变 16.5（**+10%**，玩家能直接感受到）
- 99 级 STR=200 → 物攻 300；加 1 点 STR 变 301.5（**+0.5%**，几乎无感）

**绝对增量也是 1.5**，玩家面板看到的数字根本不动。等级越往后，加点越像"白点"。

### 4. CDR / 暴击率等无硬上限

v2 文档标了"CDR 上限 40%"，但只有部分公式真正限位。极端构建（纯 INT 200+）可以堆到 60%+ 冷却缩减，破坏战斗节奏。

## 二、新设计的核心原则

1. **每个派生属性只由 1 个主属性驱动**（个别可由"主属性 × 等级倍率"叠加，但不引入第二个主属性）
2. **每个主属性 2~4 个独占派生**，组成一个清晰的"角色定位包"
3. **取消等级固定成长**，把"每级 5 自由点"作为唯一的成长入口，让玩家选择主导构建
4. **派生公式引入等级倍率**，让 1 点主属性在 99 级时的"绝对收益"比 1 级放大数倍，对抗边际稀释
5. **强制硬上限**：暴击率 75% / 暴伤 500% / 攻速 250% / 闪避 60% / 移动加成 30% / CDR 40%
6. **词条 / 装备 / Buff 走 % 乘区**，作为"扩大主属性绝对收益"的主要工具，沿用 v2 的乘区体系

---

## 三、主属性定位（5 维）

每个主属性都有一句话能讲清楚的"人设"，对应**独占的派生集合**：

| 主属性 | 缩写 | 人设 | 独占派生 |
|:---|:---|:---|:---|
| **力量 Strength** | STR | 重装爆发 + 体格 | 物理攻击力、生命上限 |
| **敏捷 Agility** | AGI | 灵巧 + 速度 + 规避 | 攻击速度、闪避、移动速度加成 |
| **智力 Intelligence** | INT | 法术 + 节奏 | 魔法攻击力、法力上限、法力回复、冷却缩减 |
| **体力 Constitution** | CON | 守备 + 续航 | 护甲、魔法抗性、生命回复 |
| **幸运 Luck** | LUK | 概率 + 收益 | 暴击率、暴击伤害、收获加成 |

派生数量：STR 2 / AGI 3 / INT 4 / CON 3 / LUK 3 = **共 15 个**，每个派生**单一主属性驱动**。

### 关于"AGI/LUK 不提供物攻基础值"

这是一个有意识的取舍。AGI/LUK 流派的输出来源**不是面板物攻**，而是：

- **AGI**：高攻速 → 单位时间内挥更多次 → 总 DPS 高
- **LUK**：高暴击率 + 高暴伤 → 偶发爆发
- **武器 `bonus_attack_power` / 装备词条 / Buff**：通过 `DAMAGE_BONUS_ALL` 等乘区，把每次出手伤害放大

也就是说：
- 战士派（STR 主）：堆物攻 → 每刀稳，靠厚血和持续输出
- 刺客派（AGI 主）：堆攻速 + 词条 → 高频小数字，靠总输出
- 赌徒派（LUK 主）：堆暴击 → 大多数普通刀 + 偶尔翻倍刀

主属性提供"地基"，装备和流派建造"上层建筑"。这是 ARPG（暗黑 / 流亡 / 暖雪）的标准做法。

### 关于"法师没有独占生命派生"

INT 不提供 HP。法师必须副堆 CON 才能不脆，这是设计上保留给"法师走玻璃大炮 vs 半坦法师"的选择空间。
如果玩家想纯法师：高魔攻 + 高 MP + 高 CDR，HP 靠装备词条和元素抗性补；如果想稳健法师：INT 主 + CON 副。

## 四、派生属性公式表

### 4.1 等级倍率（核心新机制）

为了让"高等级加点仍有绝对增量"，引入两个等级倍率（**采用保守系数**）：

| 倍率 | 公式 | 用途 |
|---|---|---|
| **AtkGrowth(L)** | `1.0 + (L - 1) × 0.012` | 攻击维度（物攻 / 魔攻） |
| **VitGrowth(L)** | `1.0 + (L - 1) × 0.007` | 生存维度（HP / 护甲 / 魔抗） |

样本值：

| 等级 | AtkGrowth | VitGrowth |
|:---:|:---:|:---:|
| 1 | 1.00 | 1.00 |
| 20 | 1.228 | 1.133 |
| 50 | 1.588 | 1.343 |
| 99 | 2.176 | 1.686 |

> 这两个系数比初稿减半（原 0.025 / 0.015），整体走"保守加成"路线，让后期更依赖装备词条 / Buff 的乘区放大，避免主属性等级倍率单独把数值推爆。

**为什么生存维度增长慢？**  
HP / 护甲是会被"百分比伤害"针对的指标（如 Boss 大招"造成 25% HP 伤害"），过度膨胀会让百分比伤害失控；进攻维度则相反，需要膨胀来对抗高等级怪物 HP。

**为什么攻速 / 暴击 / 闪避不用等级倍率？**  
这些已经有硬上限（75% / 60% / 250% / 40%）。等级倍率会让玩家"低主属性就触顶"，反而毁掉装备词条的价值空间。

### 4.2 完整派生公式表

> 表中 `L` = 角色等级；`Atk(L)` = `AtkGrowth(L)`；`Vit(L)` = `VitGrowth(L)`。

| 派生属性 | 公式 | 上限 | 驱动 |
|:---|:---|:---:|:---:|
| 物理攻击力 | `STR × 1.5 × Atk(L)` | — | STR |
| 生命上限 | `60 + STR × 12 × Vit(L)` | — | STR |
| 攻击速度 | `1.0 + AGI × 0.008` | 250% | AGI |
| 闪避 | `AGI × 0.003` | 60% | AGI |
| 移动速度加成 | `AGI × 0.001` | 30% | AGI |
| 魔法攻击力 | `INT × 1.8 × Atk(L)` | — | INT |
| 法力上限 | `30 + INT × 10` | — | INT |
| 法力回复 /s | `INT × 0.2` | — | INT |
| 冷却缩减 | `INT × 0.003` | 40% | INT |
| 护甲 | `CON × 1.2 × Vit(L)` | — | CON |
| 魔法抗性 | `CON × 0.8 × Vit(L)` | — | CON |
| 生命回复 /s | `CON × 0.4` | — | CON |
| 暴击率 | `0.05 + LUK × 0.004` | 75% | LUK |
| 暴击伤害 | `1.5 + LUK × 0.012` | 5.0 | LUK |
| 收获加成 | `LUK × 0.005` | — | LUK |

## 五、加点曲线（等级 → 属性点）

### 5.1 常量调整

| 常量 | v2 | v3 | 说明 |
|---|:---:|:---:|---|
| `PRIMARY_INITIAL`（1 级单维起始值） | 10 | **8** | 略降低基线，放大加点占比 |
| `PRIMARY_FIXED_PER_LEVEL`（每级固定成长 /维） | 1 | **0** | 取消固定成长 |
| `FREE_POINTS_PER_LEVEL`（每级自由点） | 3 | **5** | 把固定 +5 转为自由 +5 |
| `MAX_LEVEL` | 99 | **99**（不变） | |
| 经验曲线 `xp = 45 × L^1.62` | 不变 | 不变 | 阶段一不动经验，避免连带改 |

### 5.2 99 级数值预算

```
1 级各维：8
99 级累计自由点：98 × 5 = 490
理论单维上限：8 + 490 = 498（玩家把 490 全砸到一维）
玩家自主权占比：490 / (8×5 + 490) = 92.5%
```

对比 v2 的自由占比 37.5%，**玩家加点真正成为主导力**。

### 5.4 加点边际收益（验证"加点感"）

以"在 99 级 STR=200 状态下再加 1 点 STR"为例：

| 指标 | v2（无等级倍率） | v3（含 Atk(99)=2.176） |
|---|---|---|
| 物攻基础值 | 200 × 1.5 = 300 | 200 × 1.5 × 2.176 = 653 |
| +1 点的绝对增量 | +1.5 物攻 | **+3.26 物攻** |
| +1 点的相对增量 | +0.5% | +0.5%（相同） |
| HP +1 点 STR 绝对增量 | +3 HP | +12 × 1.686 = **+20.2 HP** |

**结论**：相对收益的边际递减是数学必然，但通过等级倍率把绝对增量放大约 **2.2 倍**，UI 上"点 + 之后数字明显跳"，可显著缓解"加点没感觉"。剩余的爽感缺口由装备词条 / Buff 的乘区体系补足。

## 六、伤害结算（沿用 v2）

伤害公式不变（详见 v2 § 5），但因为派生数值规模有变化，要复核**乘区平衡**：

- 全伤害加成（DAMAGE_BONUS_ALL）：词条，建议保持 0~150% 区间
- 元素伤害加成：词条，建议保持 0~200% 区间
- 暴击：见上面公式（5%~75% 几率 / 1.5x~5x 倍率）
- 护甲减伤：`armor / (armor + 100)`，护甲 600 → 减伤 86%
- 魔抗减伤：同上，400 → 减伤 80%
- 元素抗性：上限 75%

护甲 600 + 元素抗性 50% 的"全护甲战士"，对火球伤害减伤 = `1 - (1 - 0.80) × (1 - 0.50)` = **90% 减伤**。  
对于"魔攻 1875 + 全伤加成 100% + 火伤加成 100%"的法师，火球出手 1875 × 2 × 2 = 7500，落到战士身上是 7500 × 0.1 = 750 ≈ 战士 HP 的 9.4%。**单发不致死，连续轰需要法师 5~6 发**。节奏合理。

> 详细伤害推演留到实施阶段做单测验证；本文档不在公式上引入新结构。

## 七、装备词条与流派构建

v3 不改变词条系统结构（参见 v2 § 4），只是**让词条在"扩大主属性收益"上承担更重要的角色**：

| 主属性 | 推荐装备词条 | 协同逻辑 |
|---|---|---|
| STR（战士） | 全伤害加成 % / 攻击范围 / 物理穿透 | 提升每刀物攻的最终伤害 |
| AGI（刺客） | 全伤害加成 % / 攻击范围 / 吸血 | 高攻速 × 高吸血 → 续航 |
| INT（法师） | 元素伤害加成 / 法术穿透 / 元素抗性 | 单元素流派堆同色伤 |
| CON（坦克） | 全护甲 / 全魔抗 / 反伤 / HP 回 | 极致减伤 + 反伤 + 续航 |
| LUK（赌徒） | 暴击率 / 暴伤 / 异常状态几率 | 触顶后转向异常爆发 |

> 暖雪式"专精词条流派"+ Brotato 式"装备数量爆炸"是 v3 的爆发力出口。  
> 主属性提供 1.5~3× 的基础进攻乘区，装备词条提供 2~5× 的最终伤害乘区，**两者复合**得到"高级玩家强力 build"的爽感。

## 八、存档兼容与迁移

### 8.1 字段映射

旧档（v2 / 旧 v1）`progression` 段：

```json
{
  "level": 50,
  "experience": 1234,
  "unspent_attribute_points": 5,
  "allocated_attribute_points": {"str": 30, "agi": 20, "int": 15, "con": 25, "luk": 10}
}
```

字段结构 v3 完全沿用，**不引入新字段**。

### 8.2 数值迁移规则

加载旧档时，`PlayerAttributePoints.load_from_save` 做一次性补偿：

1. `level / experience / allocated` 直接保留
2. **重算 `unspent`**：  
   `expected_total_free = 98 × 5 = 490`（99 级新预算）  
   `old_earned = (level - 1) × 3 + unspent_old`  
   `new_earned = (level - 1) × 5`  
   `补偿点 = new_earned - old_earned`（加到 unspent）
3. 已分配点（allocated）**保留不动**，避免玩家被"强制重分配"

这样玩家加载旧档后，会发现：

- 自己加过的点都还在
- 未分配点变多了（升级了"每级 5 点"的新规则，把过去欠的点补上）
- 五维基础值略有下降（因为 `PRIMARY_INITIAL` 从 10 → 8、固定 +1 / 级被取消）—— 这是有意的，让玩家重新做选择

### 8.3 可选：免费一次性洗点

旧档加载时**额外给玩家一次免费洗点提示**（暂不强制实现，UI 已有"重置本页"功能即可应付）。

## 十、与战斗 / 怪物系统的衔接

### 10.1 派生公式注册位置

`CharacterAttributes._register_default_formulas()` 是唯一改动点。**所有进攻类派生现在引用 `CHARACTER_LEVEL`**，公式从"线性 a × stat"升级为"a × stat × (1 + level × k)"。

`DerivedFormula` 已经支持"线性组合 + 上下限"，但暂不支持"乘积型"（如 `STR × Atk(L)`）。可以通过下面两种方式之一实现：

**方案 A（最小侵入）**：在 `DerivedFormula` 加一个可选 `level_growth_per_level: float`，evaluate 时按  
`v = (constant + Σ coef × stat) × (1 + level × level_growth_per_level)` 计算。

**方案 B（更通用）**：把"等级倍率"作为另一个 `DerivedFormula` 字段，evaluate 时显式 lookup `CHARACTER_LEVEL`。

推荐 **A**，改动最小、最直观。

### 10.2 怪物侧

怪物属性走 `MonsterStatProfile` 配置 + `MonsterStatApplier.apply()`，**沿用同一套派生公式**。所以怪物的 HP / 物攻同样会享受等级倍率，**不需要额外改动**怪物逻辑。

但需要复核 `MonsterStatProfile` 默认值，使新公式下的怪物数值与玩家曲线匹配（参考 v2 § 10.3 怪物配合建议：普通 60% / 精英 120% / Boss 250%）。

### 10.3 怪物 HP 公式

`apply_monster_survival_formulas()` 现在是 `60 + CON × 15 + STR × 4 + L × 2`。  
建议改为与玩家 HP 公式同源：`60 + STR × 12 × Vit(L)`，并通过 `MonsterStatProfile` 的稀有度乘区 / 类型乘区在外部调节。  
**这一步留到实施阶段做平衡测试**。

## 十二、对策划/我自己的提醒

下面是我在写这份文档时**想过但没在主线里放的细节**，留作日后讨论：

1. **"洗点"成本**：v2 文档曾提"洗点 = level × 50 金"，v3 暂未实现。等加点 UI 改完再加，避免一次改太多。
2. **等级倍率参数（0.025 / 0.015）**：是凭直觉给的，需要在第一次实战测试后微调。预算 99 级 Atk 倍率落在 3.0~4.0 之间都可以接受。
3. **副属性"协同 buff"**：v2 设计原则里说"主属性之间应有协同"，v3 暂时完全砍掉了协同。后期如果发现五维太"互不相关"，可以通过 **天赋树 / Buff** 提供跨属性协同（例如"力量天赋：每 10 STR 提供 1% 暴击率"），但**不通过派生公式硬塞**，保持公式表的清晰。
4. **AGI / LUK 输出基础值低**的设计 risk 已经在 § 三末尾讨论过，结论是"主属性提供基础值、装备 / 武器 / 词条提供乘区"。需要装备掉落 / 词条池配套到位。
5. **基础属性显示**："最终值"和"基础值"在 UI 里仍然要分开（v2 现状已经支持），让玩家看清楚"自己加点了多少"vs"装备给了多少"。
6. **经验曲线**：本次**不动**。如果将来发现"等级倍率 + 加点曲线"把高等级变得过于关键，需要时再调经验曲线让中后期更平滑。
