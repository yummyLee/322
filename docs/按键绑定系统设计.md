# 按键绑定系统设计文档

> **与代码同步（已实现）**：`KeybindManager`（Autoload）、`user://keybinds.json`、`KeybindSettingsUI`（ESC 暂停菜单 →「按键绑定」）已落地；移动、冲刺、武器攻击、法术栏 1–8、双交互动作、主要 UI 与暂停/过场相关输入已走 InputMap。法术栏**技能与槽位**仍由 `SpellHotbar` + 存档 `spell_hotbar` 保存；**全局键位尚未写入 `save.json`**（见 §9）。

## 1. 现状分析

### 1.1 当前问题

- **42 处硬编码按键**散布在 14 个文件中
- **零 InputMap 动作** — project.godot 中仅有一个 `dialogic_default_action`
- **无可配置界面** — 玩家无法在游戏中修改任何按键
- **无手柄支持路径** — 所有输入直接判断 keycode，没有动作抽象层
- **按键冲突无保护** — 多个面板的 `_unhandled_input` 通过手动阻塞顺序来避免冲突

### 1.2 硬编码按键分布

```
类别          按键                         涉及文件数
──────────────────────────────────────────────────
移动          W/A/S/D                      1
战斗          Space, MouseLeft             2  
交互          E                            5 (采集点/商人/任务NPC/过场NPC/经验商人)
法术栏        Q/R/T/C/F/G/H/Y              2 (hotbar + player)
UI面板        B/P/K/J/U/I                  6
系统          Escape                       7 (暂停/关闭/取消)
过场          Escape (按住1秒)              1
对话驳回      F/Escape/Space/Enter          1
```

### 1.3 现有输入架构（迁移前快照，供对照）

```
Player._physics_process  → KeyboardInputProvider.get_move_vector()  → Input.is_key_pressed(WASD)
Player._unhandled_input  → SpellHotbar.get_bound_spell_id_for_keycode() → _cast_spell_by_id()
DashAbility._process     → Input.is_physical_key_pressed(SPACE)
各UI面板._unhandled_input → event.keycode == KEY_X → toggle/show
InteractableObject        → interact_key export 变量 (默认F，子类覆写E)
```

迁移后：上述路径已改为 `InputMap` 动作（见 §12）。可交互物改为 `interact_action: StringName`。

## 2. 设计目标

1. **统一抽象** — 所有按键操作改为通过 Godot InputMap 动作触发
2. **运行时可配** — 提供 UI 面板，玩家可以在游戏中改键
3. **持久化** — 键位配置存到磁盘，跨游戏会话保留
4. **冲突检测** — 绑定新键时检查是否被其他动作占用
5. **双端兼容** — 架构预留手柄支持，不依赖键盘特有 API
6. **低侵入迁移** — 老代码逐文件替换，不破坏现有功能

## 3. 架构设计

### 3.1 核心组件

```
KeybindManager (Autoload 单例)
├── 启动时 → load_from_disk() → 缺省则用 ACTION_MANIFEST → apply_bindings_to_input_map()
├── 运行时 → get_action_display()、find_conflicts_for_event() 等供 UI 使用
├── 确认改键 → apply_bindings_dict() → InputMap + save_to_disk() + binding_changed
└── （预留）存档 keybinds 区块 → SaveManager 尚未接入

Godot InputMap (Godot 内置)
├── 所有游戏逻辑通过 Input.is_action_pressed("move_up") 读取
└── KeybindManager 负责与 InputMap 同步

KeybindSettingsUI (CanvasLayer，`scenes/ui/keybind_settings_ui.tscn`)
├── 入口：**游戏暂停菜单**（ESC）→「按键绑定」
├── 按分类列出 `KeybindManager.ACTION_MANIFEST` 中的动作；右侧按钮显示当前键
├── 点击键位 →「… 按键中 …」→ 按下新键（或鼠标键）写入**待确认**映射；监听中 Esc 取消本次等待
└── **确认**：应用并写入 `user://keybinds.json`；**取消**：关闭不保存；**恢复默认**：立即重置并保存

user://keybinds.json (磁盘文件)
└── 存储当前绑定配置，KeybindManager 启动时读取
```

### 3.2 数据流

```
── 启动流程 ──
KeybindManager._ready()
  → 尝试读取 user://keybinds.json
  → 文件存在 → 解析 JSON → 填充绑定字典
  → 文件不存在 → 使用内置默认值 → 写入 user://keybinds.json
  → 遍历所有动作 → InputMap.action_erase_events() + action_add_event()
  → 游戏开始

── 玩家按键 ──
Player._input(event)
  → if Input.is_action_just_pressed("dash"): do_dash()
  （不需要知道键位是什么）

── 改键流程 ──
玩家打开设置 → 点击"冲刺" → 弹出"请按键..."
  → 按下 Space → KeybindManager.rebind("dash", KEY_SPACE)
  → 冲突检查: "interact" 是否也用 KEY_SPACE → 否 → 通过
  → InputMap 中移除 dash 旧绑定 → 添加新绑定
  → 更新 _bindings 字典 → 写回 user://keybinds.json
  → UI 刷新显示
```

### 4.2 键冲突策略

同一按键可以被多个动作使用（如 Escape 同时是 `pause`、`ui_cancel`、`cutscene_skip`），这是故意的——它们在不同上下文中触发不同行为，由各系统自行判断优先级。改键时会弹出冲突警告但允许强制绑定。

## 5. 存储格式

### 5.1 本地按键配置 `user://keybinds.json`

```json
{
  "version": 1,
  "bindings": {
    "dash": [
      {"type": "key", "code": 32}
    ],
    "interact": [
      {"type": "key", "code": 69}
    ],
    "weapon_attack": [
      {"type": "mouse", "code": 1}
    ],
    "spell_1": [
      {"type": "key", "code": 81}
    ],
    "pause": [
      {"type": "key", "code": 4194305}
    ]
  }
}
```

- `type`: `"key"` | `"mouse"` | `"joypad_button"` | `"joypad_axis"`
- `code`: 对应 Godot 的 `Key` / `MouseButton` / `JoyButton` / `JoyAxis` 枚举值
- 每个动作是数组，支持主键 + 备用键（一主一备）

### 5.2 存档持久化

按键配置同时写入 save.json 的 `keybinds` 区块（与 `player` / `world` / `quests` 同级）。读档时如果存档中的绑定与当前不同，弹选项：
- "使用存档中的键位" — 覆盖当前
- "保留当前键位" — 忽略存档中的

## 6. 迁移策略

### 6.1 迁移原则

- **不破坏现有功能** — 每个文件替换后立即可测试
- **渐进式** — 不需要一次性改完所有文件
- **白名单替换** — 先把 InputMap 动作注册好，然后逐个文件替换硬编码按键

### 6.2 迁移步骤

**Step 1:** 创建 KeybindManager autoload，注册所有默认绑定到 InputMap。
此时系统中并存两套输入方式：旧的硬编码按键 + 新的 InputMap 动作（同一按键，不冲突）。

**Step 2:** 逐文件替换，从最独立的开始：

```
优先级1 (UI面板，无依赖):  inventory_ui / stats_panel / skill_panel / quest_journal / debug_menus
优先级2 (游戏交互):        interactable_object / gathering_spot / merchant_npc / quest_giver_npc
优先级3 (玩家战斗):        player.gd (weapon_attack) / dash_ability
优先级4 (核心输入):        keyboard_input_provider / spell_hotbar / player.gd (spell cast)
优先级5 (系统):            game_pause_menu / cutscene / dialog
```

**Step 3:** 全部替换完成后，删除 KeyboardInputProvider（或重构为调用 InputMap）。

### 6.3 替换模式

旧代码：
```gdscript
if event is InputEventKey and event.pressed and not event.echo:
    if event.keycode == KEY_B:
        toggle_inventory()
```

新代码：
```gdscript
func _input(event: InputEvent) -> void:
    if Input.is_action_just_pressed("open_inventory"):
        toggle_inventory()
```

或者保留 context guard：
```gdscript
func _unhandled_input(event: InputEvent) -> void:
    if event.is_action_pressed("open_inventory"):
        toggle_inventory()
        get_viewport().set_input_as_handled()
```

## 7. UI 设计概要（已实现）

### 7.1 入口

**ESC** 打开 `GamePauseMenu` → 点击 **「按键绑定」** → 打开 `KeybindSettingsUI`（`CanvasLayer`，`main.tscn` 中与暂停菜单并列）。若场景无 `KeybindSettingsUI` 节点，该按钮仍可存在但不会打开面板（当前仅 `main.tscn` 挂载）。

### 7.2 布局与控件

- 标题与简短说明；`ScrollContainer` + 按 **分类**（移动 / 战斗 / 交互 / 法术栏 / 界面 / 系统 / 对话）分组的行列表。
- 每行：**中文功能名** + **按钮**（显示当前键或鼠标键中文描述）。
- 底部：`恢复默认`、`取消`、`确认`（**仅确认时**写入磁盘并刷新 InputMap）。

### 7.3 改键交互

1. 点击某一行的键位按钮 → 进入监听，文案 **「… 按键中 …」**，其它行按钮暂时禁用。
2. 按下 **键盘** 或 **鼠标键** → 更新内存中的 `pending` 映射，刷新显示；若与其它动作共用同一按键，底部显示**提示文案**（仍允许绑定）。
3. 监听中按 **Esc** → 取消监听，不修改该项 `pending`。
4. **确认**：调用 `KeybindManager.apply_bindings_dict(pending)`（内部 `apply_bindings_to_input_map`、`save_to_disk`、`binding_changed`）。
5. **取消**或关闭：丢弃 `pending`。暂停菜单在关闭时若换绑界面仍打开会先关闭换绑界面。

## 8. KeybindManager API（与脚本一致）

实现文件：`scripts/core/input/keybind_manager.gd`（Autoload 名 `KeybindManager`；**不使用**同名 `class_name`，避免与 Autoload 冲突）。

| 成员 | 说明 |
|------|------|
| `ACTION_MANIFEST` | 常量数组：每项含 `id`、`label`、`cat`、`kind`（`key`\|`mouse`）、`code` |
| `get_manifest()` | 返回 manifest 拷贝 |
| `get_action_display(action)` | 从当前 InputMap 取主事件并格式化为可读字符串 |
| `format_event_display(ev)` | 键：`as_text_physical_keycode()`；鼠标：左/右键等中文 |
| `serialize_event` / `deserialize_event` | 与 `user://keybinds.json` 结构对应 |
| `get_all_bindings_copy()` | 深拷贝当前 `_bindings`（供 UI 编辑） |
| `apply_bindings_dict(data)` | 用 UI 提交的映射更新 `_bindings`、同步 InputMap、保存、发信号 |
| `find_conflicts_for_event(ev, except_action, pending)` | 在 `pending` 下查找与 `ev` 冲突的动作 id 列表 |
| `rebind_action_in_pending(pending, action, ev, out_conflict)` | 单次改键写入 `pending`；Esc 键不绑定 |
| `reset_to_defaults()` | 恢复内置默认并保存 |
| `save_to_disk()` / `load_from_disk()` | `user://keybinds.json`，`version: 1` |
| `binding_changed` | 无参数信号；`SpellHotbar` 监听以刷新槽位键提示 |

**未实现**（原草案）：`get_action_keys`、`is_bound`、单独 `rebind()` 返回 `Error`、`export_for_save` / `import_from_save` 与 SaveManager 联动。

## 11. 未来扩展

- **手柄适配**：只需在 `user://keybinds.json` 中为每个动作加 `{"type": "joypad_button", "code": X}`，InputMap 自动处理
- **组合键**：在 bindings 中扩展 `modifiers` 字段（`ctrl`/`shift`/`alt`）
- **配置方案**：允许多套键位方案（如"默认"、"FPS风格"），一键切换
- **云端同步**：将 keybinds.json 内容上传到玩家账号
