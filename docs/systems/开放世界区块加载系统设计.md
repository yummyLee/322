# 开放世界区块加载系统设计

> **适用场景**：`chapter1_world.tscn` 扩展 + 后续章节无限大地图  
> **关联系统**：`MonsterSpawner / WorldItem / LootTable / SaveManager`  
> **约定**：1 格 = 16 px；ChunkCoord `(0,0)` 为赤水村所在区块

---

## 一、核心目标

| 目标 | 说明 |
|------|------|
| 帧率安全 | 运行时只保留玩家周围 N 圈区块；远处区块完整卸载（含节点树） |
| 无限可扩 | 坐标系基于 `Vector2i`，理论上支持无限地图 |
| 数据驱动 | 每块可用 `ChunkDef` Resource 完全自定义内容；未配置的块走程序化默认规则 |
| 采集 / 刷怪 | 每块内置随机采集物节点 + 可选 MonsterSpawner |
| 存档安全 | 玩家采集或击杀后状态持久化；区块重载时还原 |

---

## 二、坐标体系

### 2.1 区块尺寸

```
CHUNK_GRIDS = 256          → 每块 256×256 格
CHUNK_SIZE_PX = 4096       → 每块 4096×4096 px（= 256 × 16）
```

赤水村布局（`Chapter1LayoutBuilder`）占 240×420 格，完整覆盖在 **1×2 块**内（`(0,0)` + `(0,1)`）。

### 2.2 坐标转换

```
ChunkCoord  ← world_pos / CHUNK_SIZE_PX  (floor 取整)
LocalPos    ← world_pos - chunk_origin   (chunk_origin = coord * CHUNK_SIZE_PX)
```

### 2.3 初期目标：5×5 布局

以赤水村为中心，初期建立 **5×5 = 25 块** 的可探索地图：

```
col:  -2   -1    0    1    2
row:
-2  [山]  [山]  [山]  [山]  [山]
-1  [林]  [林]  [村北][林]  [林]
 0  [野]  [野]  [赤水村][野][野]
 1  [野]  [林]  [村南][林]  [野]
 2  [山]  [山]  [山]  [山]  [山]
```

（以上为规划方向，最终内容见区块 ChunkDef 文件）

## 三、数据资源

### 3.1 `ChunkDef`（Resource）

```
res://resources/chunks/chunk_{x}_{y}.tres
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `chunk_coord` | `Vector2i` | 坐标标识（仅记录用，加载时以文件名为准） |
| `terrain_type` | `TerrainType` enum | 地形类型，控制地面色块与 BGM |
| `collectibles` | `Array[ChunkCollectibleEntry]` | 采集点列表 |
| `spawner_rules` | `Array[ChunkSpawnerRule]` | 怪物生成规则列表 |
| `reward_loot_table` | `LootTable` | 区块完成奖励（可为空） |
| `custom_scene` | `PackedScene` | 可选：整块替换为手工场景（如 Boss 房） |
| `proc_seed_override` | `int` | 0 = 用坐标哈希；非 0 = 固定种子（便于手工调整随机结果） |

### 3.2 `ChunkCollectibleEntry`（Resource）

| 字段 | 类型 | 说明 |
|------|------|------|
| `local_position` | `Vector2` | 相对区块原点的位置 |
| `item_id` | `String` | ItemDatabase key |
| `qty_min / qty_max` | `int` | 掉落数量范围 |
| `respawn_minutes` | `float` | 0 = 不刷新；>0 = 重生时间 |
| `persist_key` | `String` | 非空时参与存档（默认为空→每次区块加载都出现） |

### 3.3 `ChunkSpawnerRule`（Resource）

| 字段 | 类型 | 说明 |
|------|------|------|
| `local_position` | `Vector2` | Spawner 节点位置 |
| `spawn_rule` | `MonsterSpawnRule` | 沿用现有 MonsterSpawnRule |
| `trigger` | `SpawnTrigger` enum | `ON_ENTER`（进块即刷）/ `ALWAYS`（定时循环刷） |
| `cooldown_sec` | `float` | 刷新冷却 |
| `max_alive` | `int` | 区块内同时存活上限 |

### 3.4 地形类型（TerrainType enum）

```
VILLAGE   → 暖土黄地面，日常 BGM
FOREST    → 深绿，林道 BGM
MOUNTAIN  → 灰岩，低沉 BGM
FIELD     → 田野绿，晨间 BGM
RUINS     → 暗褐，静默 BGM
```

## 四、运行时架构

### 4.1 节点树

```
Chapter1World (Node2D)
├── World/Layout          ← 赤水村静态布局（现有）
├── ChunkRoot (Node2D)    ← 所有动态区块的父节点
│   ├── Chunk_0_0 (ChunkNode)
│   │   ├── Ground        ← 地面色块
│   │   ├── Collectibles  ← WorldItem 节点
│   │   └── Spawners      ← MonsterSpawner 节点
│   └── Chunk_1_0 (ChunkNode)
│       └── ...
├── Entities (y_sort)
└── ...
```

### 4.2 `ChunkNode`（Node2D，运行时创建）

职责：
- 持有区块内所有子节点
- 暴露 `load_chunk(def)` / `unload_chunk()` 接口
- 进入/离开"活跃区"时通知 Spawner 启停

**状态机**

```
LOADING  → ACTIVE (玩家半径内，Spawner 运行)
         → DORMANT (玩家近距但超活跃半径，节点存在但 Spawner 暂停)
         → UNLOADED (节点完全释放)
```

### 4.3 `WorldChunkLoader`（Autoload 或 chapter1_world 子节点）

核心循环（每秒检查一次，非 `_process`）：

```
player_coord = floor(player.global_position / CHUNK_SIZE_PX)

需要 LOAD 的块  = coords in [player_coord ± load_radius]  但未加载
需要 UNLOAD 的块 = 已加载 但坐标 > unload_radius
活跃半径内的块   = coords in [player_coord ± active_radius]

逐帧分批处理（每帧最多加载/卸载 2 块）
```

**半径默认值**

| 参数 | 默认 | 说明 |
|------|------|------|
| `load_radius` | 2 | 加载玩家周围 5×5 块 |
| `active_radius` | 1 | 怪物/AI 仅 3×3 块内激活 |
| `unload_radius` | 3 | 超出范围才卸载（避免反复抖动） |

## 五、程序化内容生成

当区块没有对应 `ChunkDef.tres` 文件，或 `ChunkDef.custom_scene` 为空时，走**程序化默认规则**。

### 5.1 种子

```
seed = hash(Vector2i(cx, cy)) if proc_seed_override == 0 else proc_seed_override
rng = RandomNumberGenerator.new()
rng.seed = seed
```

### 5.2 采集物随机规则

| 地形 | 草药密度 | 矿物密度 |
|------|----------|----------|
| VILLAGE | 低（1–2 株） | 无 |
| FOREST | 高（4–8 株） | 低（0–1） |
| MOUNTAIN | 无 | 高（3–6） |
| FIELD | 中（2–4 株） | 无 |

生成方式：在区块内用泊松盘采样放置点，每点从对应品级的物品池随机取 item_id。

### 5.3 怪物密度规则

| 地形 | 怪物数（packs） | 刷新触发 |
|------|-----------------|---------|
| VILLAGE | 0 | — |
| FOREST | 1–2 团 | ON_ENTER |
| MOUNTAIN | 2–4 团 | ALWAYS (120s) |
| RUINS（规划中）| 3–5 团 | ON_ENTER + ALWAYS |

## 六、奖励系统

### 6.1 区块首次清空奖励（可选）

`ChunkDef.reward_loot_table` 非空时：玩家击杀该区块最后一只怪后触发，掉落到场景中心。

```
区块怪物全灭 → reward_loot_table.roll() → WorldItem.spawn_at(center, ...)
```

### 6.2 采集奖励

采集点 `qty_min/max` 控制数量；品级影响后续合成/出售价格，与 `ItemData.rarity` 对应。

### 6.3 稀有宝箱（规划）

`ChunkDef` 中可放置 `ChunkLootNode`（Area2D，一次性），包含 `LootTable` 资源，交互后开箱。

## 七、存档持久化

存档结构新增 `chunk_states` 段：

```json
"chunk_states": {
    "0,0": {
        "collected": ["herb_windgrass_0_0_01", "ore_copper_0_0_03"],
        "spawner_last_kill_time": { "spawner_a": 1234567890 }
    },
    "1,0": { ... }
}
```

| 事件 | 操作 |
|------|------|
| 玩家采集（`persist_key` 非空） | 写入 `chunk_states[coord].collected` |
| 区块卸载 | 把 ChunkNode 运行时状态序列化进 chunk_states |
| 区块加载 | 读取 chunk_states 恢复状态（已采集节点隐藏/标 consumed） |

采集物 `persist_key` 命名约定：`{item_id}_{cx}_{cy}_{local_index}`  
例：`herb_windgrass_0_0_01`

## 八、性能预算与优化策略

| 策略 | 实现 |
|------|------|
| 分帧加载 | 每帧最多实例化 2 个区块，避免单帧卡顿 |
| 静态碰撞 | 地形 / 建筑用 `StaticBody2D`，加载后 `set_process(false)` |
| 采集物轻量 | 使用 `Area2D` 而非 `CharacterBody2D`，靠近才绘制图标 |
| Spawner 休眠 | 超出 active_radius 时 `spawner.set_process(false)` |
| 渲染剔除 | `VisibleOnScreenNotifier2D` 控制 Label / 光效节点 |
| 采集物合批 | 同一区块采集物共用 CanvasLayer，减少 DrawCall |
| 无限地图内存 | 已卸载区块节点完全释放；状态只存 dict（极小） |

### 内存估算（load_radius = 2）

| 已加载区块 | 节点数/块 | 总节点数 |
|-----------|----------|---------|
| 5×5 = 25  | ~50–100  | ~1500   |

每个 Node2D ~200–400 bytes，1500 节点约 **0.5 MB**，可接受。

## 十、与第一章集成

1. `chapter1_world.gd` 持有 `WorldChunkLoader` 节点
2. 赤水村内容继续由 `Chapter1LayoutBuilder.build_into($World/Layout)` 静态生成（不分块）
3. 赤水村**外围区块**由 ChunkLoader 动态管理
4. 周边区块的地形类型/采集物/怪物全部通过 `ChunkDef.tres` 配置，或走程序化默认

```
chapter1_world.tscn 中：
  World/Layout  ← 赤水村固定内容（不参与 chunk 管理）
  ChunkRoot     ← 动态区块（ChunkLoader 管理）
```

## 十一、无限地图扩展路径

1. 初期（5×5 = 25 块）：全部手工 ChunkDef，有明确边界
2. 中期（程序化扩展）：超出边界的块走 `WorldChunkProcGen`，用坐标哈希保证一致性
3. 后期（流式 + 存档）：加入 ChunkState 持久化，玩家可随时保存/读档，世界状态完整还原

边界控制：`WorldChunkLoader` 配置 `max_coord_extent: Vector2i`，超出时拒绝加载（5×5 时 `(±2, ±2)`，无限时设为极大值）。
