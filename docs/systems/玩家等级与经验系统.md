# 玩家等级与经验系统

## 设计意图

- **与 `Player` 解耦**：等级、经验、升级逻辑放在可挂载组件 **`PlayerProgression`** 中；不需要的角色可不挂；`Player` 脚本不持有 `level/experience` 字段。
- **职责拆分**：自由属性点分配从 PlayerProgression 拆出到独立组件 **`PlayerAttributePoints`**，二者通过 Player 上的桥接信号解耦。
- **统一经验入口**：所有经验来源（击杀、任务、商人购买、道具）经 **`XpReceiver`** 进入；详见 [`击杀怪物经验系统`](./击杀怪物经验系统.md)。
- **曲线参数**：`scripts/player/player_level_curve.gd` 定义幂次增长公式与满级上限。

---

## 组件结构

```
Player
├── PlayerProgression        ← 等级/经验（信号驱动）
├── PlayerAttributePoints    ← 自由属性点（信号驱动）
├── XpReceiver               ← 经验入口（→ progression.add_experience）
├── CombatantComponent
└── ...
```

| 资源 | 说明 |
|------|------|
| `scripts/components/player_progression.gd` | `PlayerProgression`：`level / experience`、升级循环、信号 |
| `scripts/components/player_attribute_points.gd` | `PlayerAttributePoints`：`unspent / allocated`、提交分配、旧档迁移、相关常量 |
| `scripts/player/player_level_curve.gd` | 静态 `xp_required_to_advance(current_level)`、常量 `MAX_LEVEL`（默认 99） |
| `scripts/components/xp_receiver.gd` | 经验入口；详见击杀经验系统文档 |
| `scenes/player.tscn` | 默认含 `PlayerProgression` 与 `PlayerAttributePoints` 子节点 |

## 在 `Player` 上的访问

```gdscript
player.get_progression()      # → PlayerProgression / null
player.get_attribute_points() # → PlayerAttributePoints / null
XpReceiver.find_on(player)    # → XpReceiver / null
```

发经验：

```gdscript
# 推荐：走 XpReceiver（贯穿加成 / 飘字 / HUD 通路）
XpReceiver.find_on(player).receive_xp(100, &"item")

# 直接调用 progression（绕过加成与飘字，仅用于内部恢复存档）
player.get_progression().add_experience(100)
```

## 经验曲线

从当前 **L** 升到 **L+1** 在本段内需要的经验：

\[
\text{need} = \mathrm{round}(45 \times L^{1.62})
\]

- **L** 取 `clamp` 在 \([1,\, \text{MAX\_LEVEL}-1]\)
- **满级**：`current_level >= MAX_LEVEL` 时 `xp_required_to_advance` 返回 **0**；满级后 `add_experience` 不累积

## 信号

### PlayerProgression

| 信号 | 用途 |
|------|------|
| `experience_changed(level, experience, xp_to_next)` | UI 经验条刷新；满级时 `xp_to_next == 0` |
| `leveled_up(new_level)` | 每升一级触发一次 |

### PlayerAttributePoints

| 信号 | 用途 |
|------|------|
| `allocation_changed(unspent_points)` | 加点 UI 余额刷新 |

### 桥接（在 `Player._setup_progression_attribute_sync` 中连接）

- `PlayerProgression.leveled_up` → `PlayerAttributePoints.grant_for_levels(1)`：每升一级发放 `FREE_POINTS_PER_LEVEL` 个自由点
- `PlayerProgression.leveled_up / experience_changed` → `Player.sync_primary_stats_from_progression()`：把固定主属性与等级写回 `CombatantComponent / CharacterAttributes`
- `PlayerAttributePoints.allocation_changed` → 同上：分配点变化时同步五维

## 主属性数值（PlayerAttributePoints 常量，v3）

| 常量 | 默认 | 含义 |
|------|------|------|
| `PRIMARY_INITIAL` | 8 | 1 级单维主属性初始值 |
| `PRIMARY_FIXED_PER_LEVEL` | 0 | v3 取消固定成长，让加点完全主导构建 |
| `FREE_POINTS_PER_LEVEL` | 5 | 每升一级获得的可分配点（v2 是 3） |

详细设计与曲线推演见 [`../narrative/角色属性v3.md`](../narrative/角色属性v3.md) §5。

辅助静态函数：

```gdscript
PlayerAttributePoints.fixed_primary_total_at_level(lv)     # 固定部分总和
PlayerAttributePoints.total_free_points_earned_at_level(lv) # 累计应得自由点
PlayerAttributePoints.primary_stat_keys()                   # [&"str", &"agi", &"int", &"con", &"luk"]
```

## 加点 UI（v3：合并到主属性页）

`PlayerStatsPanel`（快捷键 P）：

- **2 个 Tab**：主属性（含加点）、派生属性。**v3 取消了独立的"加点" Tab**，把 `[-] [+]` 按钮直接放在每行主属性上。
- 顶部展示等级倍率（攻击 ×Atk / 生存 ×Vit）+ 自由点余额 + 挂起信息 + 确认/重置按钮
- 每行主属性：名称 | 进度条 | 当前值 | `[-]` | `[+]` | 数值分解（固定/自由/挂起/基础/最终）| 收益提示
- 派生属性按主属性色标着色，单主属性驱动后预览只显示真正变化的项
- 加点页：会话级 pending → "确认分配" 调 `PlayerAttributePoints.commit(delta)`
- 关闭面板：丢弃未确认分配
- 余额不足时 `+` 按钮置灰，`commit` 返回 false 不修改任何状态

## 存档兼容

`save.json` 中 `player.progression` 段结构保持向后兼容：

```json
{
  "level": 1,
  "experience": 0,
  "unspent_attribute_points": 0,
  "allocated_attribute_points": {"str": 0, "agi": 0, "int": 0, "con": 0, "luk": 0}
}
```

`PlayerRuntimeState` 序列化时合并 `PlayerProgression.serialize_for_save()` 与 `PlayerAttributePoints.serialize()` 两段；反序列化时按字段拆开传给两个组件。

旧档无 `allocated_attribute_points` 时，`PlayerAttributePoints.load_from_save` 通过 `combat.base_str / base_agi / ...` 与等级反推 allocated（详见组件源码的 `_migrate_from_legacy_combat`）。

## 金币购买经验（经验商人 UI）

- **场景**：`scenes/world/experience_trader_npc.tscn`（橙块 NPC，靠近按 **E**）；主场景 `main.tscn` 已实例化。
- **界面**：`ExperiencePurchaseUI`（`scenes/ui/experience_purchase_ui.tscn`），`CanvasLayer` 高于普通 HUD；**ESC** 关闭并清空预购。
- **兑换比例**：检查器 `gold_cost_per_experience`（默认 `1.0`）。
- **交互**：**+** 累加一档"本段尚缺经验"，**−** 撤销最后一档；本档费用 = `ceil(尚缺经验 × gold_cost_per_experience)`。
- **结算**：按下 **确定** 时扣金币并通过 **`XpReceiver.receive_xp(_, &"purchase")`** 入账（与击杀经验共用加成/飘字/HUD 通路）。`XpReceiver` 缺失时回退到 `PlayerProgression.add_experience`。
