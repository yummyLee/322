# 法术系统设计记录

## 1. 目标

- 法术逻辑可在任意场景复用，不依赖固定 `.tscn`。
- 法术具备施术者归属，伤害仅作用于敌对目标。
- 与现有战斗系统对齐，统一走 `HitContext + CombatantComponent` 伤害链路。
- **视觉 / 贴图**：新法术实现需遵守 [法术视觉与贴图替换约定](../conventions/法术视觉与贴图替换约定.md)（可选 `Texture2D` + 程序绘制兜底）。

## 2. 冷却时间系统

### 2.1 设计概述

- 实现时间：2026-04-12
- 目标：防止技能过于频繁使用，增加策略性和平衡性

### 2.2 技术实现

- 存储方式：使用毫秒时间戳（`Time.get_ticks_msec()`）
- 数据结构：`_spell_cooldowns: Dictionary`，key 为法术 ID，value 为冷却结束时间戳
- 比较方式：当前时间戳 < 存储的结束时间戳 = 在冷却中

### 2.3 核心 API

```gdscript
# 检查法术是否在冷却中
SpellSystem.is_spell_on_cooldown(spell_id: String) -> bool

# 设置法术冷却时间（cooldown_seconds 为秒数）
SpellSystem.set_spell_cooldown(spell_id: String, cooldown_seconds: float) -> void

# 获取法术剩余冷却时间（秒），已就绪时返回 0.0
SpellSystem.get_spell_cooldown_remaining(spell_id: String) -> float

# 获取冷却进度比例：1.0 = 刚进入冷却，0.0 = 已就绪（供 UI 绘制扇形遮罩使用）
SpellSystem.get_spell_cooldown_fraction(spell_id: String) -> float
```

当前已注册的 spell_id（同时也是 `spell_hotbar.gd.spell_catalog` 的目录项）：

|---|---|---|

| `ground_root` | 禁锢 | 延迟 + 形状约束禁锢圈 |
| `cone_volley` | 锥弹 | 鼠标锥形方向连续弹幕 |

| `earth_triple_quake` | 地脉三震 | 三段震地 |
| `soul_lantern` | 引魂灯 | 延时灯标 + 连杀触发 |
| `frost_trail` | 冰霜轨迹 | 自身铺冰 + SlowBuff；见 `../spells/冰霜轨迹设计记录.md` |
| `gravity_well` | 重力阱 | 吸引 + 结束眩晕；见 `../spells/重力阱设计记录.md` |

### 2.6 施放逻辑

1. 玩家按下技能键
2. 检查 `SpellSystem.is_spell_on_cooldown(spell_id)`
3. 如果在冷却中，直接返回，不播放施放动画
4. 如果不在冷却中，播放施法动画并调用法术系统
5. 法术系统设置冷却时间

## 3. 当前实现结构

### 3.1 全局入口

- Autoload：`SpellSystem`
- 配置位置：`project.godot`
- 脚本：`scripts/magic/spell_system.gd`

作用：
- 提供统一施法 API。
- 管理延迟结算与范围命中查询。
- 将命中目标转发到已有受击接口（`receive_hit` / `on_hit`）。

### 3.2 视觉预警（无场景依赖）

- 脚本：`scripts/magic/effects/spell_ground_marker.gd`
- 类型：`Node2D`，使用 `_draw()` 动态绘制。

作用：
- 在地面显示范围圈与进度环。
- 到点由 `SpellSystem` 清理节点。

### 3.3 阵营与敌对判定

- 脚本：`scripts/core/combat/faction_utils.gd`
- 角色接入：
  - `scripts/player/player.gd`（默认 `player`）
  - `scripts/enemies/enemy_base.gd`（默认 `enemy`）
  - `scripts/test/test_dummy.gd`（默认 `enemy`）

判定策略：
- `caster_faction != target_faction` 视为敌对。
- 若任一方是 `neutral`，不视为敌对。

## 4. 第一个法术：延迟地爆术

接口：

`SpellSystem.cast_delayed_ground_blast(caster, center, radius, delay_seconds, base_damage, damage_type, collision_mask, cast_delay, cooldown_seconds)`

执行流程：

1. 检查冷却时间，如果在冷却中则直接返回。
2. 创建并显示地面预警圈。
3. 启动一次性 `Timer`。
4. 超时后使用 `intersect_shape(CircleShape2D)` 查询圆形范围内碰撞体。
5. 将碰撞体映射到可受伤目标（本体或父节点）。
6. 去重后进行敌对判定（归属生效）。
7. 构建 `HitContext`，调用 `receive_hit`（fallback 到 `on_hit`）。
8. 设置法术冷却时间。

伤害来源标识：
- `ctx.source_tag = "spell:delayed_ground_blast"`

冷却时间：默认 3.0 秒

---

## 5. 第二个法术：延迟禁锢圈

接口：

`SpellSystem.cast_delayed_ground_root(caster, center, radius, delay_seconds, root_duration, collision_mask, cast_delay, cooldown_seconds)`

执行流程：

1. 检查冷却时间，如果在冷却中则直接返回。
2. 显示地面预警圈（蓝色系，和伤害圈区分）。
3. `delay_seconds` 后触发范围查询与敌对过滤。
4. 若圈内存在敌对单位，生成持续 `root_duration` 秒的实体禁锢圈。
5. 禁锢圈由 `StaticBody2D + CollisionPolygon2D(BUILD_SEGMENTS)` 构成圆环边界。
6. 敌人碰到边界后无法穿出，时间到自动销毁。
7. 设置法术冷却时间。

控制实现说明：
- 可视化：`Line2D` 蓝色圆环
- 阻挡层：禁锢圈碰撞体放在 layer 1（默认可与角色/怪物阻挡）

冷却时间：默认 4.0 秒

## 6. 锥形持续矩形弹幕

接口：

`SpellSystem.cast_cone_rect_volley(caster, duration, cone_angle_deg, cone_length, spawn_interval, bullet_speed, bullet_max_range, bullet_damage, damage_type, cast_delay, cooldown_seconds)`

脚本：

- 控制器：`scripts/magic/effects/cone_volley_controller.gd`（挂到当前场景，每帧同步施术者位置，锥轴指向鼠标）
- 弹体：`scripts/magic/effects/spell_cone_rect_bullet.gd`（`Area2D` + 矩形碰撞，`_draw` 画橙色条）

行为要点：

1. 检查冷却时间，如果在冷却中则直接返回。
2. 持续 `duration`（默认 5 秒），施术者仍可移动；控制器 `global_position` 每帧等于施术者。
3. 锥半角 = `cone_angle_deg / 2`（默认整锥约 30°），在 `[-半角, +半角]` 内**随机偏角**发射，形成多角度弹幕。
4. 每 `spawn_interval` 一波，每波随机 `1~3` 发（可在控制器里改 `bullets_per_wave_*`）。
5. 锥形区域用半透明扇形 + 边线绘制，随鼠标旋转。
6. 弹体 `collision_mask` 含地形(1)与敌人身体(2)；命中无受击主体的刚体时销毁；命中敌对且可 `receive_hit` 时结算魔法伤害，`source_tag = spell:cone_rect_volley`。
7. 设置法术冷却时间。

冷却时间：默认 6.0 秒

玩家测试：`T`（与 `spell_west` 施法动画共用鼠标朝向逻辑）。

## 7. 为什么这样设计

- 不依赖 `.tscn`：法术逻辑完全由脚本驱动，减少资源耦合。
- 复用现有战斗公式：无需重复防御、抗性、暴击等计算。
- 通过归属 + 阵营控制目标：便于后续扩展友军治疗、敌我混战、召唤物继承归属等。
- 通过全局入口统一管理：冷却系统已实现，蓝耗、法术队列、日志与调试开关待扩展。

---

## 8. 当前限制

- 目前是代码直接调用，尚未抽象成法术资源配置（如 `SpellData`）。
- 命中查询默认只查 `body`（`collide_with_areas = false`）。
- 单一敌对规则为“阵营不同即敌对”，未支持更复杂关系（临时同盟、PVP 白名单等）。

---

## 9. 后续扩展建议

> 施法组件化已落地：每个可施法主体挂 **`SpellCasterComponent`**（`scripts/magic/spell_caster_component.gd`），用 `@export_group` 把各法术参数分组；`cast_xxx(target)` 统一读本组件参数再调 `SpellSystem.cast_xxx`。`Player` 在 `_ready` 时用 `_wrap_component_cast_at_mouse` 把它们映射到 `_spell_casters` 表供快捷栏触发。

剩余可选项：

1. **法术数据化**：把 `SpellCasterComponent` 里的字段拆成 `SpellData`（Resource），便于 NPC 共享配置。
2. **目标过滤器**：支持目标类型过滤（仅生物、仅敌方、仅可见目标）。
3. **效果层分离**：伤害、控制、治疗、Buff 拆分成可组合 Effect（Buff 这条已在 `./Buff系统设计记录.md` 里推进）。
4. **网络/回放友好**：施法参数与命中结果结构化，便于同步与回放。

## 11. 技能快捷栏 UI（SpellHotbar）

> 详细 UI 设计请看 `./技能面板与技能栏设计记录.md`；本节只保留与 `SpellSystem` 的交互口。

### 11.1 功能概述

屏幕左下角显示多个正方形技能槽，实时反映每个技能的冷却状态：

- **就绪**：显示技能名称，边框正常亮度
- **冷却中**：显示灰色扇形遮罩（从 12 点方向顺时针覆盖，类似英雄联盟效果）+ 白色倒计时文字（保留一位小数，单位 s）
- 左上角常驻显示按键提示（每个槽独立）
- 默认槽位见 `spell_hotbar.gd.slot_configs`（当前为 Q/R/T/E/F/G/H/Y 共 8 个）；玩家可在技能面板（`skill_panel.gd`）里把 `spell_catalog` 中任一法术拖到任意槽。

### 11.2 实现结构

| 文件 | 说明 |
|------|------|
| `scripts/ui/spell_hotbar.gd` | CanvasLayer（layer 13），纯代码构建，含内部类 `_SpellSlot` |
| `scenes/player.tscn` | 新增 `SpellHotbar` 子节点，挂载上述脚本 |

### 11.3 扇形绘制原理

- `_SpellSlot` 继承 `Control`，开启 `clip_contents = true`
- 在 `_draw()` 里用 `draw_polygon` 绘制扇形多边形（圆心 + 弧上点列）
- 扇形半径 = 槽尺寸（60px），大于正方形对角距（≈ 42px），超出部分被裁切
- 覆盖比例 = `SpellSystem.get_spell_cooldown_fraction(spell_id)`（由新增 API 提供）

字段说明：
- `spell_catalog` 是**可被拖到槽位的候选池**，由技能面板呈现；必填 `spell_id`、`display_name`。

- `display_name` 展示时从 `spell_catalog` 里查对应 `spell_id` 获取。

### 11.5 冷却系统新增 API

为支持 UI 绘制，`spell_system.gd` 新增：
- `_spell_cooldown_durations` 字典：在 `set_spell_cooldown` 时同步记录总时长
- `get_spell_cooldown_remaining()` → 剩余秒数（用于倒计时文字）
- `get_spell_cooldown_fraction()` → 进度比例（用于扇形遮罩面积）


玩家实际施法由 `Player._spell_casters` 表驱动（见 `scripts/player/player.gd`），它在 `_ready` 把 `SpellCasterComponent.cast_xxx` 包成 `Callable`；按键 / 快捷槽由 `SpellHotbar` 触发。需要在脚本里手动调法术时，建议 **直接调 `SpellCasterComponent.cast_xxx(target_point)`** 而不是 `SpellSystem.cast_xxx(...)`，以便沿用组件里配置的数值（包括可选贴图）。
