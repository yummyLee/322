# 地图建筑碰撞与遮挡虚化

> 实现：`MapBuilding` + `map_building_base.gdshader` + `map_building_occlusion.gdshader`  
> 预制体：`scenes/world/map_building.tscn`  
> 首版落地：窑村 v1 背景图场景 `scenes/chapter1/yaocun_v1_map.tscn` · `House1` / `well1` / `House2`（多段脚底 + 门洞）/ `House6`（多段脚底 + 双门）  
> **实现总览**（多块碰撞 + 图层 + 进门联动）：[窑村地图建筑进门与图层实现记录](./窑村地图建筑进门与图层实现记录.md)  
> **地形阻挡**（树林/悬崖等不可走区域）：[地图地形阻挡碰撞](./地图地形阻挡碰撞.md)

---

## 一、要解决的问题

俯视角地图上的独立建筑贴图需要同时满足：

| 需求 | 说明 |
|------|------|
| **脚底碰撞** | 只有墙根/基座阻挡玩家，屋顶区域可「走进去」 |
| **遮挡虚化** | 玩家进入 `OcclusionArea` 时，建筑**屋顶区**渐变为半透明，露出玩家轮廓 |
| **正确图层** | 虚化时**只有屋顶**画在玩家上方；地基、前景墙、侧墙等非虚化区域**始终在玩家下方** |

---

## 二、设计原则

1. **组件即功能**：`.tscn` 只组装节点；逻辑集中在 `MapBuilding` 脚本 + 专用 shader。
2. **脚底 footprint 碰撞**：`StaticBody2D` 下挂矩形和/或多边形，不参与整张贴图包围盒碰撞。
3. **OcclusionArea = 检测区 = 虚化区**：同一矩形同时用于「玩家是否在遮挡范围」与 shader 渐变区域，避免编辑器里框与运行时效果不一致。
4. **场景形状优先**：运行时 `_ready` 从 `CollisionShape2D` **读回**尺寸；在 2D 视图里直接改形状即可，不会被脚本默认值覆盖。
5. **与 Player 同级 y_sort**：建筑须与 `Player` 同为 `y_sort_enabled` 父节点（如 `Entities`）的**直接子节点**；中间不能再套一层 `Buildings`，否则排序失效。
6. **双层绘制（标准做法）**：**禁止**虚化时把整张贴图 `z_index` 提到玩家上方——必须用底层 + 叠加层分离「非虚化像素」与「虚化像素」的图层。

---

## 三、坐标与前后关系

俯视角 **Y 轴向南**（向下为正）：

```
        北（地图上方，y 更小）
            ↑
    ┌── OcclusionArea ──┐  ← 渐变虚化矩形（仅此处叠在玩家上方）
    │      屋顶/墙体      │
    ├─ 地面线（矩形南缘）─┤
    │   FootCollision    │  ← 脚底碰撞（可阻挡）；贴图始终走底层
            ↓
        南（地图下方，y 更大）
```

| 玩家位置 | 碰撞 | 虚化 | 图层 |
|----------|------|------|------|
| 在 `OcclusionArea` 外 | 视 footprint | 不触发 | 整张贴图走 **VisualBase**（建筑 `z_index = -1`，玩家在前景） |
| 在 `OcclusionArea` 内 | 可进入上半区 | 触发，自南向北渐强 | **VisualBase** 在 fade_bounds 内挖空；**VisualOcclude** 绝对 `z_index` 叠在玩家上方 |
| 建筑南侧 / 侧墙前（y_sort） | footprint 阻挡 | 不触发 | 整张贴图走 **VisualBase**，玩家在前景 |

**前后关系**：南侧 y 更大 = 更靠近镜头前景。玩家与建筑的前后主要由 `Entities.y_sort_enabled` 决定；建筑根节点固定 `z_index = -1`，保证非虚化区域默认在玩家下方。

## 四、节点结构（双层 Visual · 标准）

```
MapBuilding (Node2D, map_building.gd, z_index = -1)
├── VisualBase (Sprite2D)          # 或旧场景名 Visual；底层贴图 + base shader
├── VisualOcclude (Sprite2D)       # 虚化叠加层 + occlusion shader；运行时无则自动创建
├── FootCollision (StaticBody2D)   # layer=1, mask=8（玩家层）
│   ├── CollisionShape2D           # 矩形 footprint（可多个）
│   └── CollisionShape2D …         # 侧墙、门洞左右墙基等
└── OcclusionArea (Area2D)         # layer=0, mask=8
    ├── CollisionShape2D           # 矩形遮挡/虚化范围（可多个，最多 8）
    └── CollisionShape2D …
```

### 关联文件

| 路径 | 职责 |
|------|------|
| `scripts/components/map_building.gd` | 碰撞同步、遮挡检测、双层 Visual、图层 |
| `shaders/map_building_base.gdshader` | 底层：`occlude_strength > 0` 时在 `fade_bounds` 内 alpha=0（挖空） |
| `shaders/map_building_occlusion.gdshader` | 叠加层：仅在 `fade_bounds` 内绘制半透明贴图 |
| `scenes/world/map_building.tscn` | 可实例化预制体 |

### 兼容旧场景

- 仅有 `Visual` 节点时，脚本将其当作 **VisualBase**，并在 `_ready` 自动创建 **VisualOcclude**。
- 无需批量改已有 `.tscn`；新预制体建议直接使用 `VisualBase` + `VisualOcclude` 命名。

## 五、碰撞（FootCollision）

- **形状**：
  - `CollisionShape2D` + `RectangleShape2D`（轴对齐矩形，旧用法仍可用）；
  - **`CollisionPolygon2D`**（倾斜墙根 / 不规则轮廓，推荐）。
- **物理层**：`collision_layer = 1`（障碍），`collision_mask = 8`（与 `player.tscn` 的 `CharacterBody2D` 一致）。
- **调法**：
  - 矩形：选中 `FootCollision/CollisionShape2D`，改 **Size / Position**；或改 `footprint_size` / `footprint_offset`（**仅写回第一块矩形**）。
  - 多边形：选中 `FootCollision/CollisionPolygon2D`，在 2D 视图拖顶点。

建议 footprint 对齐建筑贴图**最南缘**墙基/门廊，不要包住整栋屋顶。

### 多边形脚底（倾斜 / 异形建筑）

`FootCollision` 下挂一个或多个 `CollisionPolygon2D`：

| 画法 | 门洞 |
|------|------|
| 左右两块，中间留空 | 与多矩形相同，空隙 ≥8px 即门洞 |
| **整块 U 形**（南侧凹口为门） | 对最南一缘采样并按 x 聚类，凹口两侧各成一簇 → 自动出门洞 |

**添加步骤**：

1. 右键房子实例 → **可编辑子节点**；
2. 右键 `FootCollision` → 添加 `CollisionPolygon2D`；
3. 沿墙根描点（可旋转、斜边，无需多块旋转矩形）；
4. 有门时：南侧留凹口，或拆成左右两块；
5. 原矩形 `CollisionShape2D` 不用可删或勾选 Disabled。

多边形与矩形可混用；门洞推断对两者统一处理。

### 多块矩形脚底（不规则建筑）

`FootCollision` 下可挂**多个** `CollisionShape2D`（均为矩形），用于：

| 用途 | 示例 |
|------|------|
| 南墙左右墙基 | `House2` / `House6`：左右墙基，中间留门洞 |
| 侧墙阻挡 | `House2` / `House6`：左右侧墙、前景矮墙 |
| 室内门槛 / 后墙 | `House2`：`CollisionShape2D5`（建筑北侧内墙） |

**添加步骤**：

1. 右键 `FootCollision` → 添加子节点 `CollisionShape2D`；
2. 新建或引用**独立** `RectangleShape2D`（复制实例后须 Make Unique，见第八节）；
3. 在 2D 视图按贴图微调每块 Size / Position；
4. 运行验证：每块独立阻挡；门前 / 侧墙前玩家图层正确（见第七节）。

**Export 兼容**：`footprint_size` / `footprint_offset` 只同步**第一块矩形**；多边形与其余块仅在编辑器里维护。

### 门洞推断（供进门对齐）

当 `FootCollision` **最南一排**出现 ≥2 个脚底块（矩形，或多边形南缘；同行容差约 56px），且相邻块水平空隙 ≥8px 时，`get_door_gaps_local()` / `_refresh_door_gaps()` 自动记录门洞，供室外门 `sync_width_from_foot_gap` 对齐门槛宽度。**门洞推断不参与虚化触发**（虚化只看 `OcclusionArea` 重叠）。

## 六、遮挡与渐变虚化（OcclusionArea + 双层 Shader）

### 触发条件（当前实现 · 简化）

玩家 `CharacterBody2D`（`player` 组）与 `OcclusionArea` **碰撞体重叠**即触发：

- `_players_in_zone` 非空 → `occlude_strength` 向 `1` 渐变；
- 离开区域 → 向 `0` 渐变（速度由 `fade_speed` 控制）。

**编辑器注意**：`OcclusionArea` 只框**屋顶/上半部**，不要向下包住门前可站立空地；框过大会在门口误触发虚化。

### 虚化形状

`OcclusionArea` 下可挂**多个** `CollisionShape2D`（最多 **8** 块，受 shader `fade_bounds[8]` 限制）。

每块的世界包围盒写入 shader 参数 `fade_bounds`（`Vector4`：`min_x, min_y, max_x, max_y`）。叠加层多块时取各块渐变强度的 **max**。

矩形内像素按高度渐变：

- **南缘**（`grad = 0`）：几乎不虚化；
- **北缘**（`grad = 1`）：虚化最强，alpha 约为 `occluded_alpha`（默认 `0.38`）。

公式：`alpha *= mix(1.0, occluded_alpha, occlude_strength * grad)`

### 双层 Shader 分工（标准 · 以后都这样处理）

| 层 | Shader | `occlude_strength > 0` 时行为 |
|----|--------|--------------------------------|
| **VisualBase** | `map_building_base.gdshader` | `fade_bounds` **内**像素 alpha=0（挖空屋顶，避免与叠加层重复） |
| **VisualOcclude** | `map_building_occlusion.gdshader` | `fade_bounds` **外** alpha=0；**内**按渐变绘制半透明贴图 |

两层共用同一 `building_texture`、同一 `fade_bounds` / `occlude_strength` 参数；`_setup_shader()` 为每个实例 `new` 两份独立 `ShaderMaterial`。

### 调法

- 编辑器：改各 `OcclusionArea/CollisionShape2D` 的 Size / Position；
- Inspector：改 `occlusion_size`、`occlusion_offset`（仅第一块）。

## 七、图层（双层 Visual + 绝对 z_index）

**核心规则**：虚化时**不能**提升整栋建筑根节点 `z_index`，否则地基、前景墙等非虚化贴图会盖住玩家。

### 当前实现（`_update_draw_order`）

| 节点 | `z_as_relative` | `z_index` | 说明 |
|------|-----------------|-----------|------|
| `MapBuilding` 根 | — | **-1** | 建筑整体默认在玩家下方 |
| `VisualBase` | `true` | `0` | 相对根节点，有效约 **-1** |
| `VisualOcclude` | **`false`** | **`10`**（`_OCCLUDE_Z_ABSOLUTE`） | 虚化激活时可见；**绝对** z，参与视口全局排序，叠在玩家（约 `0`）上方 |
| `VisualOcclude`（未虚化） | `false` | `0` | `visible = false` |

### 为什么需要 `z_as_relative = false`

`VisualBase` / `VisualOcclude` 是 `MapBuilding` 的子节点，与 `Player` **不是兄弟节点**。子节点相对 `z_index` 无法与 `Entities` 下的 `Player` 直接比较。

- 底层：靠建筑根 `z_index = -1` + `y_sort` 保证非虚化区域在玩家下方。
- 叠加层：靠 **`z_as_relative = false` + 绝对 `z_index`**，使虚化屋顶真正画在玩家上方。

### 典型问题与修复（2026 · House6）

| 现象 | 错误做法 | 正确做法 |
|------|----------|----------|
| 虚化时地基/前景墙盖住玩家头顶 | 虚化时整节点 `z_index = 1` | **双层 Visual**：仅 `VisualOcclude` 用绝对 z；`VisualBase` 始终走底层 |
| 屋顶半透明但下方又有一层不透明屋顶 | 单层 shader 只改 alpha | Base 层在 `fade_bounds` 内挖空 + Occlude 层绘制半透明 |
| 门口误虚化 | `OcclusionArea` 框过大 | 只框屋顶；与玩家碰撞体重叠才触发 |
| 子节点 z 无法压过玩家 | 仅设 `VisualOcclude.z_index = 1`（相对父节点） | 设 `z_as_relative = false`，用绝对 z（当前 `10`） |

### 验收要点

- 建筑**南侧** / **侧墙前** / **门洞前**：玩家完整挡住建筑（不被基座、矮墙裁切）。
- 进入 **`OcclusionArea`**：屋顶渐变虚化，且半透明屋顶在玩家**上方**。
- 同一张贴图上：虚化区与非虚化区**图层行为不同**（这是双层方案存在的原因）。

## 八、多实例碰撞独立化（House1 / well1 等）

### 现象

从 `House1` **复制**出 `well1` 后，只改了 `well1` 的碰撞 **Size**，`House1` 的碰撞框也跟着变。

### 原因

多个 `MapBuilding` 实例都引用 **`map_building.tscn` 预制体里同一份 `RectangleShape2D` SubResource**。  
在 Godot 里，SubResource 是**共享资源**：改一份 Shape 的 `size`，所有仍指向它的实例都会变。

只改 **Position** 不会触发这个问题；改 **Size** 才会。

### 运行时兜底

`MapBuilding._ready()` 里会对 `FootCollision`、`OcclusionArea` 的 shape 执行 `duplicate()`，**进游戏后**各实例互不干扰。  
但**在编辑器里改 Size** 仍须下面任一做法，否则保存场景时仍会串改。

### 做法 A：Shape 独立化（复制实例后首选）

1. 在场景树 **右键 `well1`** → **可编辑子节点**（Editable Children）  
   - 实例节点右侧有 **场记板图标**，默认**没有展开三角**，不是 bug。
2. 展开后进入 `FootCollision/CollisionShape2D`、`OcclusionArea/CollisionShape2D`。
3. 选中 `CollisionShape2D`，在 Inspector → **Shape** 一行点 **「独立化」**（Make Unique）。
4. 两个 CollisionShape2D **都要**独立化。
5. 再改 **Size / Position**，保存 `yaocun_v1_map.tscn`。

### 做法 B：父场景写独立 SubResource（工程当前用法）

在 `yaocun_v1_map.tscn` 顶层为每个实例声明**不同 id** 的 `RectangleShape2D`，并在实例 override 里引用（详见历史版本本节）。

### 复制实例推荐流程

```text
1. 实例化 map_building.tscn → 命名 well1
2. 设 building_texture、position、scale
3. 右键 well1 → 可编辑子节点
4. FootCollision、OcclusionArea 的 CollisionShape2D 各 Make Unique
5. 在 2D 视图按贴图微调矩形
6. 运行：改 well1 时不应影响 House1
```

## 九、新增建筑（标准步骤）

1. 在场景中准备 **`y_sort_enabled = true`** 的父节点（如 `Entities`）。
2. 实例化 `scenes/world/map_building.tscn`，与 **`Player` 同级**（不要嵌套在额外空节点下）。
3. 设置 `building_texture`、位置、`scale`。
4. **右键实例 → 可编辑子节点**；对 `CollisionShape2D` **Make Unique**（见第八节）。
5. 在 2D 视图选中实例：
   - 调 `FootCollision` 下 `CollisionShape2D`（矩形）或 `CollisionPolygon2D`（倾斜/异形）→ 墙根 / 门洞；
   - 调 `OcclusionArea` 下各 `CollisionShape2D` → **仅屋顶**虚化范围。
6. 运行验证（见第七节验收要点）。
7. 若场景里还有其它 `MapBuilding`，改本实例碰撞时**不应**带动其它实例。

### 代码估算初值（可选）

`MapBuilding._fit_footprint_to_texture()` 可按贴图像素尺寸估算 footprint / occlusion，适合首版占位；**最终以编辑器微调为准**。

## 十、Export 速查

| 属性 | 含义 |
|------|------|
| `building_texture` | 建筑贴图（同步到 VisualBase + VisualOcclude） |

## 十一、已知限制与扩展

| 项 | 说明 |
|----|------|
| 多实例 Shape | 预制体 SubResource 默认共享；须 Make Unique 或父场景独立 SubResource（见第八节） |
| 形状 | 当前仅支持矩形 `RectangleShape2D` |
| 脚底 / 遮挡块数 | 脚底不限；OcclusionArea 最多 8 块（shader 数组上限） |
| 多玩家 | `_players_in_zone` 列表，任一在区内即触发 |
| 门洞 | 最南一排多块 footprint（矩形或多边形南缘簇）留隙 → `get_door_gaps_local()`；进门切场景见室内门文档 |
| 图层 | **标准**：双层 Visual + Base/Occlude shader + 绝对 z；勿回归单层整图提 z |
| Export 写回 | `footprint_*` / `occlusion_*` 仅同步第一块 CollisionShape2D |
| 出生点在 Occlusion 内 | `_sync_players_in_zone()` 延迟扫描重叠体，避免漏触发 |
