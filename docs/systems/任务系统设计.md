# 任务系统设计

## 1. 文档目的

- 定义一套 **单机 RPG 任务系统** 的完整架构：从任务定义、NPC 对话分支、多任务并行跟踪、目标进度更新、到 UI 展示与存档持久化。
- 与 `docs/剧情设计fable5v1.md` 配套：**叙事文档管「什么剧情什么节拍」**，本文管 **「系统怎么驱动这些节拍」**。（旧配套文档《主线任务流程设计》已删除）
- 遵循项目中已有的设计惯例：数据/实例分离、autoload 服务层、信号解耦、Resource 定义。

## 2. 核心问题拆解

在动手写代码之前，先回答几个最容易让任务系统失控的问题。

### 2.1 NPC 怎么知道自己现在在哪个任务流程？

**答案：NPC 不存任务状态，只向 QuestManager 查询。**

NPC 交互分两层：

```
玩家靠近 NPC → 按交互键
  → NPC 调用 QuestManager.get_relevant_quests(npc_id)
  → QuestManager 遍历所有进行中的任务，找出该 NPC 参与的
  → 返回 [(quest_id, stage_id, dialogue_branch), ...]
  → NPC 取最高优先级的，播放对应对话
```

NPC 身上只挂一个 `npc_id: String`。所有任务相关逻辑集中在 QuestManager 里，NPC 自身是"无状态的演员"。

**对话分支的决策优先级**（NPC 响应哪个任务）：
1. 主线任务中该 NPC 处于"待交互"阶段 → 最高优先级
2. 该 NPC 发起的支线任务处于"待交付"阶段
3. 该 NPC 发起的支线任务处于"可接取"阶段
4. 无任务相关 → 播放默认闲聊

### 2.2 如果有多个任务又该怎么设计？

**答案：每个任务是一个独立的轻量状态机，QuestManager 持有所有任务实例的字典。**

```
QuestManager
  ├── _active_quests:  Dictionary[quest_id → QuestInstance]
  ├── _completed_quests: Dictionary[quest_id → CompleteTime]
  └── _failed_quests:    Dictionary[quest_id → FailReason]
```

多个任务之间 **完全独立运行**，互不阻塞。一个玩家可以同时持有：
- 1 条主线任务（进行中）
- N 条支线任务（进行中）
- M 条已接取但未推进的任务

**任务间交互**通过事件触发，不用硬编码关联：
- 任务 A 的完成会自动发出 `quest_completed("quest_a")` 信号
- 任务 B 的某个阶段可以监听这个信号作为"解锁条件"

### 2.3 整体任务流程怎么跟踪？

**答案：任务 = 阶段链表 + 条件门控。**

每个任务定义为一个 **有序阶段列表**：

```
Quest: "血路来客"
  Stage 0 "发现陆鸿"    → 完成条件: 靠近倒地的陆鸿(触发区域)
  Stage 1 "护送进屋"    → 完成条件: 到达周伯草屋(触发区域)
  Stage 2 "打水生火"    → 完成条件: 打水(交互水井) + 生火(交互灶台)
  Stage 3 "检视遗物"    → 完成条件: 交互木匣
```

每个 Stage 内部结构：
- `entry_actions`：进入阶段时触发（刷新 NPC 对话、生成敌人、播放演出）
- `objectives`：该阶段需要完成的目标列表（平行或串行）
- `completion_condition`：所有目标完成的判定方式（ALL / ANY / SEQUENCE）
- `on_complete`：阶段完成时触发（推进到下一阶段、给奖励、切换场景）
- `next_stage`：下一阶段 ID（null 表示任务完成）

**QuestInstance** 是运行时的任务状态：

```
QuestInstance
  quest_def: Resource       # 指向 QuestDef
  current_stage: int        # 当前阶段编号
  stage_progress: Dictionary # { objective_id → current_value }
  is_active: bool
```

### 2.4 任务中要求完成的行为怎么更新到任务流程？

**答案：全局事件总线 + 目标匹配器。**

这是整个系统最关键的部分。当玩家做了一个动作（杀怪、拾取、对话、走到某地），对应的游戏系统发出一个 **全局事件**。QuestManager 监听所有事件，检查是否有进行中任务的目标能匹配上。

```
玩家杀死 "黑衣人"
  → CombatantComponent 发出 signal: enemy_killed(enemy_id="black_robe", position=...)
  → QuestManager._on_enemy_killed(enemy_id):
       for each active quest:
         for each objective in current stage:
           if objective.type == KILL_ENEMY and objective.target == enemy_id:
             objective.current += 1
             if objective.current >= objective.required:
               _check_stage_completion(quest)
```

**目标类型枚举**（按项目中已有的系统覆盖）：

| 目标类型 | 触发事件来源 | 匹配字段 |
|---------|-------------|---------|
| `KILL_ENEMY` | `CombatantComponent.enemy_died` | `enemy_id` |
| `COLLECT_ITEM` | `Inventory.inventory_changed` | `item_id` |
| `TALK_TO_NPC` | `InteractableObject.interacted` | `npc_id` |
| `ENTER_AREA` | `Area2D.body_entered` | `area_id` |
| `USE_SKILL` | `SpellSystem.spell_cast` | `spell_id` |
| `REACH_LEVEL` | `PlayerProgression.level_up` | `level` |
| `HOLD_ITEM` | `Inventory.inventory_changed` | `item_id`（不消耗，仅检查拥有） |
| `CUSTOM` | 脚本手动调用 `QuestManager.advance_objective()` | `custom_key` |

### 2.5 数据流全景

```
[游戏世界事件]                    [QuestManager]                    [UI 层]
                                                                   
敌人死亡 ──────┐               ┌─────────────────┐            QuestJournal
物品拾取 ──────┼── 全局信号 ──→│ 目标匹配器       │            (任务列表)
NPC交互 ───────┤               │  ↓              │               │
进入区域 ──────┘               │ 更新阶段进度     │               │
               │               │  ↓              │               │
               │               │ 检查阶段完成条件  │               │
               │               │  ↓              │               │
               │               │ 执行 on_complete │               │
               │               │  ↓              │               │
               │               │ 推进到下一阶段    │── quest_updated → 刷新UI
               │               │  ↓              │               │
               │               │ 执行 entry_actions│              │
               │               └─────────────────┘            QuestTracker
                                                               (当前追踪)
[存档系统] ←── 序列化 ──────── QuestManager._active_quests
```

## 3. 数据结构定义

### 3.1 QuestDef（任务定义，Resource）

```
class_name QuestDef
extends Resource

## 任务唯一 ID（如 "main_1_2"、"side_hunter_bow"）
@export var quest_id: String = ""
## 显示名称
@export var quest_name: String = ""
## 任务描述（给玩家的正文，{vars} 可替换）
@export var description: String = ""
## 任务类型
@export var quest_type: QuestType = QuestType.SIDE
## 阶段列表（按 0, 1, 2, ... 排序）
@export var stages: Array[StageDef] = []
## 接取条件（前置任务列表）
@export var prerequisites: Array[String] = []
## 是否可重复接取
@export var repeatable: bool = false
## 失败条件（可选，为空则永不失败）
@export var fail_condition: FailCondition = FailCondition.new()
## 奖励定义
@export var rewards: Array[RewardDef] = []
## 任务给予者 NPC（用于地图标记）
@export var giver_npc_id: String = ""
## 交付目标 NPC
@export var turn_in_npc_id: String = ""
```

### 3.2 QuestType 枚举

| 值 | 说明 |
|----|------|
| `MAIN` | 主线任务，不可放弃，不可拒绝 |
| `SIDE` | 支线任务，可接可不接 |
| `REPEATABLE` | 可重复任务（每日/每周委托） |
| `HIDDEN` | 隐藏任务，不显示在日志中直到某条件触发 |

### 3.3 StageDef（阶段定义，Resource）

```
class_name StageDef
extends Resource

## 阶段编号（在 quest 内唯一）
@export var stage_id: int = 0
## 阶段标题（如"寻找陆鸿"）
@export var stage_title: String = ""
## 阶段目标列表
@export var objectives: Array[ObjectiveDef] = []
## 完成方式
@export var completion_mode: CompletionMode = CompletionMode.ALL
## 入口动作（进入该阶段时执行一次）
@export var entry_actions: Array[QuestAction] = []
## 完成动作（该阶段所有目标达成时执行一次）
@export var on_complete_actions: Array[QuestAction] = []
## 该阶段涉及的 NPC 对话映射
@export var npc_dialogues: Dictionary = {}  # { npc_id → dialogue_resource }
```

**CompletionMode**：
- `ALL`：所有目标必须完成
- `ANY`：任意一个目标完成即可
- `SEQUENCE`：必须按 objectives 数组顺序依次完成

### 3.4 ObjectiveDef（目标定义，Resource）

```
class_name ObjectiveDef
extends Resource

## 目标唯一 key（在 stage 内唯一，用于进度追踪）
@export var objective_key: String = ""
## 目标类型
@export var type: ObjectiveType = ObjectiveType.KILL_ENEMY
## 匹配目标 ID（敌人 id / 物品 id / NPC id / 区域 id）
@export var target_id: String = ""
## 需求数量
@export var required_count: int = 1
## 目标描述（给玩家看的，如"击杀黑衣人 0/3"）
@export var display_text: String = ""
## 是否隐藏进度（不显示计数器，仅完成时通知）
@export var hidden: bool = false
## 可选目标（不影响阶段推进）
@export var optional: bool = false
```

### 3.5 ObjectiveType 枚举

```
enum ObjectiveType {
    KILL_ENEMY,      # 击杀指定敌人
    COLLECT_ITEM,    # 拾取/获得指定物品（会消耗）
    TALK_TO_NPC,     # 与指定 NPC 完成对话
    ENTER_AREA,      # 进入指定区域
    USE_SKILL,       # 使用指定技能
    REACH_LEVEL,     # 达到指定等级
    HOLD_ITEM,       # 持有指定物品（不消耗，仅检查拥有数量）
    INTERACT_OBJECT, # 交互指定场景物体
    ESCORT_NPC,      # 护送 NPC 到指定区域
    SURVIVE_TIME,    # 在指定区域内生存指定时长
    CUSTOM,          # 脚本手动触发
}
```

### 3.6 QuestAction（动作定义）

```
class_name QuestAction
extends Resource

@export var action_type: QuestActionType
@export var params: Dictionary = {}  # 不同 action 的参数
```

**QuestActionType**：

| 类型 | params | 说明 |
|------|--------|------|
| `SET_NPC_DIALOGUE` | `{npc_id, dialogue_res}` | 切换 NPC 对话内容 |
| `SPAWN_ENEMY` | `{enemy_id, position, count}` | 生成敌人 |
| `GIVE_ITEM` | `{item_id, quantity}` | 直接给玩家物品 |
| `TAKE_ITEM` | `{item_id, quantity}` | 从背包移除物品 |
| `PLAY_CUTSCENE` | `{cutscene_path}` | 播放过场 |
| `SHOW_MESSAGE` | `{text}` | 弹出消息 |
| `SET_WORLD_FLAG` | `{flag_name, value}` | 设置世界状态标志 |
| `UNLOCK_SKILL` | `{skill_id}` | 解锁技能 |
| `TELEPORT_PLAYER` | `{scene_path, position}` | 传送玩家 |
| `TRIGGER_QUEST` | `{quest_id}` | 自动接取另一任务 |
| `FAIL_QUEST` | `{quest_id}` | 强制失败另一任务 |

### 3.7 QuestInstance（运行时实例）

```
class_name QuestInstance
extends RefCounted

var quest_def: QuestDef
var current_stage: int = -1    # -1 表示已接取但未开始（等待入口条件）
var stage_progress: Dictionary = {}  # { objective_key → current_value }
var is_active: bool = true
var started_at: float = 0.0    # OS.get_ticks_msec() 接取时间
var variables: Dictionary = {} # 任务内变量（{var_name → value}，用于对话替换）
```

## 4. 核心组件：QuestManager

### 4.1 职责

QuestManager 是 autoload 单例，负责：

1. **加载任务定义**：启动时从 `resources/quests/` 加载所有 `QuestDef`
2. **管理任务实例**：启动/暂停/完成/失败任务
3. **监听全局事件**，匹配活跃任务的目标
4. **处理阶段推进**：检查条件 → 执行动作 → 进入下一阶段
5. **提供查询接口**：给 NPC、UI、存档系统调用

### 4.2 核心 API

```gdscript
# === 任务生命周期 ===
func start_quest(quest_id: String) -> QuestStartResult
func complete_quest(quest_id: String) -> void
func fail_quest(quest_id: String, reason: String) -> void
func abandon_quest(quest_id: String) -> bool  # 仅支线可放弃

# === 进度操作 ===
func advance_objective(quest_id: String, objective_key: String, amount: int = 1) -> void
func set_objective(quest_id: String, objective_key: String, value: int) -> void

# === 查询（给 NPC / UI 用）===
func get_active_quests() -> Array[QuestInstance]
func get_quest_instance(quest_id: String) -> QuestInstance
func get_relevant_quests_for_npc(npc_id: String) -> Array[QuestInstance]
func get_current_dialogue(npc_id: String) -> Resource  # 返回该 NPC 当前应播放的对话
func is_quest_completed(quest_id: String) -> bool
func is_quest_active(quest_id: String) -> bool
func get_objective_progress(quest_id: String, objective_key: String) -> int

# === 世界状态 ===
func get_world_flag(flag_name: String) -> Variant
func set_world_flag(flag_name: String, value: Variant) -> void

# === 信号 ===
signal quest_started(quest_id: String)
signal quest_completed(quest_id: String)
signal quest_failed(quest_id: String, reason: String)
signal quest_stage_changed(quest_id: String, stage_id: int)
signal objective_updated(quest_id: String, objective_key: String, current: int, required: int)
signal world_flag_changed(flag_name: String, value: Variant)
```

### 4.3 事件监听 —— 核心循环

```
QuestManager._ready():
    连接全局信号：
    CombatantComponent.enemy_died      → _on_enemy_died
    Inventory.inventory_changed         → _on_inventory_changed
    InteractableObject.interacted       → _on_object_interacted
    PlayerProgression.level_up          → _on_level_up
    SpellSystem.spell_cast              → _on_spell_cast
    场景触发器(Area)                     → _on_area_entered (通过 group)
```

```gdscript
func _on_enemy_died(enemy_id: String) -> void:
    for quest in _active_quests.values():
        if not quest.is_active:
            continue
        var stage = quest.quest_def.stages[quest.current_stage]
        for obj in stage.objectives:
            if obj.type == ObjectiveType.KILL_ENEMY and obj.target_id == enemy_id:
                quest.stage_progress[obj.objective_key] = quest.stage_progress.get(obj.objective_key, 0) + 1
                objective_updated.emit(quest.quest_def.quest_id, obj.objective_key,
                    quest.stage_progress[obj.objective_key], obj.required_count)
                _check_stage_completion(quest)
```

### 4.4 阶段推进流程

```
_check_stage_completion(quest):
    stage = quest.quest_def.stages[quest.current_stage]
    if stage.completion_mode == ALL:
        all_done = all(obj.optional or quest.stage_progress.get(obj.objective_key, 0) >= obj.required_count for obj in stage.objectives)
    elif stage.completion_mode == ANY:
        any_done = any(quest.stage_progress.get(obj.objective_key, 0) >= obj.required_count for obj in stage.objectives)
    elif stage.completion_mode == SEQUENCE:
        # 按顺序检查，当前未完成的目标阻塞后续
        ...

    if completed:
        _execute_actions(stage.on_complete_actions, quest)
        _advance_to_next_stage(quest)

_advance_to_next_stage(quest):
    next_stage_id = quest.quest_def.stages[quest.current_stage].next_stage_id
    if next_stage_id < 0:  # 任务完成
        _finish_quest(quest)
    else:
        quest.current_stage = next_stage_id
        quest.stage_progress.clear()
        quest_stage_changed.emit(quest.quest_def.quest_id, next_stage_id)
        _execute_actions(quest.quest_def.stages[next_stage_id].entry_actions, quest)
```

## 5. NPC 对话分支系统

### 5.1 NPC 如何根据任务切换对话

NPC 场景节点持有 `npc_id`，在其 `_ready()` 中：

```gdscript
# NPC.gd
@export var npc_id: String = ""

func _on_interacted(_obj) -> void:
    var dialogue = QuestManager.get_current_dialogue(npc_id)
    if dialogue:
        DialogueUI.show(dialogue)
    else:
        DialogueUI.show(default_dialogue)
```

QuestManager 内部：

```gdscript
func get_current_dialogue(npc_id: String) -> Resource:
    for quest in _active_quests.values():
        if not quest.is_active:
            continue
        var stage = quest.quest_def.stages[quest.current_stage]
        if npc_id in stage.npc_dialogues:
            return stage.npc_dialogues[npc_id]
    return null  # 走默认闲聊
```

### 5.2 对话中的条件分支

对话资源支持简单条件：

```
DialogueNode:
    text: "你已经拿到了木匣？"
    conditions:
        - type: HAS_ITEM
          item_id: "wooden_box"
    on_accept:
        - action: COMPLETE_OBJECTIVE
          params: { quest_id: "main_1_5", objective_key: "talk_to_zhou" }
```

对话不再是纯文本链，而是可以：
- **检查条件**：是否有某物品、某任务阶段、某世界标志
- **触发效果**：推进任务、给物品、改变 NPC 态度

## 6. 多任务并行与冲突处理

### 6.1 并行策略

每个任务实例独立维护自己的 `stage_progress`。同一个玩家行为可以同时推进多个任务：

```
玩家击杀 "forest_wolf"
  → 主线任务 "清除狼群" 的目标 "kill_wolves" +1
  → 支线任务 "猎户的请求" 的目标 "wolf_pelts" +1
  → 可重复任务 "每日狩猎" 的目标 "daily_kills" +1
```

### 6.2 NPC 对话冲突 —— 优先级规则

当 NPC 同时参与多个进行中的任务时：

| 优先级 | 情况 | 说明 |
|--------|------|------|
| 1 (最高) | 有任务处于"等待与该 NPC 对话"的阶段 | 当前阶段 objective 是 `TALK_TO_NPC` 且 target 为此 NPC |
| 2 | 有任务处于"可向该 NPC 交付"的阶段 | 当前阶段已完成，`turn_in_npc_id` 为此 NPC |
| 3 | 有任务处于"可向该 NPC 接取"的阶段 | `giver_npc_id` 为此 NPC 且未接取 |
| 4 | 默认 | 播放 NPC 的通用/氛围对话 |

### 6.3 互斥任务

部分任务互斥（选了 A 就不能选 B），通过 `prerequisites` 和 `world_flag` 实现：

```gdscript
# 任务 A 完成后设置 world_flag
on_complete_actions:
    - action: SET_WORLD_FLAG
      params: { flag_name: "chose_path_a", value: true }

# 任务 B 的接取条件检查此 flag
prerequisites:
    # 前置任务
    - "main_1_3"
    # 互斥条件（通过 fail_condition 实现）
fail_condition:
    type: WORLD_FLAG
    params: { flag_name: "chose_path_a", value: true, message: "你已选择了另一条路" }
```

## 7. UI 层设计

### 7.1 QuestJournal（任务日志）

- 按 `J` 打开/关闭
- 左侧列表：所有活跃任务（主线置顶，按接取时间排序）
- 右侧详情：当前阶段标题、目标列表（含进度条）、任务描述
- 已完成任务归档到"已完成"标签页

### 7.2 QuestTracker（屏幕追踪器）

- 屏幕右侧/左上角常驻显示 1-3 个勾选"追踪"的任务
- 每个显示：任务名 + 当前目标文本 + 进度（如"击杀黑衣人 2/5"）
- 任务阶段变化时短暂高亮动画
- 可手动切换追踪哪个任务

### 7.3 信号驱动刷新

UI 不轮询，只订阅信号：

```
QuestManager.quest_started         → Journal 添加条目
QuestManager.quest_stage_changed   → Journal 刷新详情 + Tracker 刷新
QuestManager.objective_updated     → Tracker 更新进度条
QuestManager.quest_completed       → 弹出"任务完成"提示 + 移入归档
QuestManager.quest_failed          → 变灰 + 标记失败原因
```

## 8. 存档与持久化

### 8.1 存档内容

QuestManager 序列化以下数据到存档文件：

```json
{
  "quests": {
    "active": [
      {
        "quest_id": "main_1_4",
        "current_stage": 2,
        "stage_progress": { "kill_black_robes": 3, "protect_house": 1 },
        "started_at": 1234567890,
        "variables": {}
      }
    ],
    "completed": ["main_1_0", "main_1_1", "main_1_2", "main_1_3"],
    "failed": [],
    "world_flags": {
      "chose_evacuate": true,
      "got_wooden_box": true
    }
  }
}
```

### 8.2 恢复流程

1. 加载存档 JSON
2. `QuestManager.restore_from_save(data)`
3. 重建所有 `QuestInstance`（状态完全恢复）
4. 重建 `world_flags`
5. 执行每个活跃任务的当前 stage 的 `entry_actions`（重新应用世界状态：NPC 对话、敌人刷新等）

## 9. 与现有系统的集成点

### 9.1 InteractableObject 扩展

当前 `interactable_object.gd` 只发 `interacted` 信号。需要增加：

```gdscript
@export var object_id: String = ""  # 用于任务目标匹配

func _on_interacted(_obj) -> void:
    if not object_id.is_empty():
        QuestManager._on_object_interacted(object_id)
```

NPC 同理，需增加 `npc_id` 字段并在交互时通知 QuestManager。

### 9.2 Enemy 扩展

```gdscript
# enemy_base.gd 死亡时
func _die() -> void:
    QuestManager._on_enemy_died(enemy_id)
```

### 9.3 Area 触发器

场景中的 `Area2D` 可通过 group `"quest_trigger"` 标识。QuestManager 连接每个触发器的 `body_entered`，匹配 `ENTER_AREA` 目标。

### 9.4 ItemDatabase / Inventory

物品拾取时 `Inventory.inventory_changed` 已存在，QuestManager 监听它并检查 `COLLECT_ITEM` / `HOLD_ITEM` 目标。

## 10. 任务定义工作流（给策划/开发者）

### 10.1 创建新任务的步骤

1. **在 `resources/quests/` 下创建 `.tres` 文件**（QuestDef Resource）
2. **填写基本字段**：`quest_id`、`quest_name`、`quest_type`
3. **定义阶段**：每个 `StageDef` 包含目标、入口动作、完成动作
4. **配置对话**：在对应 NPC 的 DialogueDef 中添加条件分支
5. **设置触发条件**：
   - 主线任务：上一任务完成后自动触发
   - 支线任务：NPC 对话框中给出接取选项
   - 触发区域：玩家进入某区域后自动弹出

### 10.2 快速参考：常见任务模板

**击杀类**：
```
objectives:
  - type: KILL_ENEMY, target_id: "forest_wolf", required_count: 5, display_text: "击杀森林狼"
```

**收集类**：
```
objectives:
  - type: COLLECT_ITEM, target_id: "wolf_pelt", required_count: 3, display_text: "收集狼皮"
```

**对话类**：
```
objectives:
  - type: TALK_TO_NPC, target_id: "zhou_bo", required_count: 1, display_text: "与周伯交谈"
```

**探索类**：
```
objectives:
  - type: ENTER_AREA, target_id: "qingzhou_gate", required_count: 1, display_text: "抵达青州城门"
```

**复合类**（同一阶段多个目标）：
```
objectives:
  - key: "get_water", type: INTERACT_OBJECT, target_id: "well", required_count: 1
  - key: "get_herbs", type: COLLECT_ITEM, target_id: "herb_bundle", required_count: 2
completion_mode: ALL
```
