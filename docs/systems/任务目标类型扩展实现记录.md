# 任务目标类型扩展 — 实现记录

> 对应 [`核心循环补全详细设计.md`](../核心循环补全详细设计.md) §3。在首期 KILL_ENEMY 框架上实装 COLLECT_ITEM / TALK_TO_NPC / ENTER_AREA / CUSTOM，并为每种类型提供主场景可测的示例任务。

## 1. 实现范围

| 目标类型 | 推进入口 | 进度语义 |
|---|---|---|
| KILL_ENEMY | `notify_enemy_killed(enemy_id)` | 累加 +1 |
| COLLECT_ITEM | 监听 `Inventory.inventory_changed` → `_sync_collect_objectives` | **按当前持有量重算**（丢弃会回退） |
| TALK_TO_NPC | `notify_npc_talked(npc_id)` | 累加 +1 |
| ENTER_AREA | `notify_area_entered(area_id)` | 累加 +1 |
| CUSTOM | `advance_objective(quest_id, objective_id, amount)` | 累加（默认 +1） |

存档：`SaveManager` 已通过 `export_quest_state` / `import_quest_state` 序列化 `progress` 字典；读档后会 `deferred` 重算 COLLECT_ITEM 进度。

## 3. 数据流（COLLECT_ITEM）

```
Player.inventory.inventory_changed
    ↓
QuestManager._sync_all_collect_objectives()
    ↓
对每个 ACTIVE 任务的 COLLECT_ITEM 目标：
  owned = inventory.count_item_by_id(target_id)
  QuestInstance.set_progress(oid, min(owned, required))
    ↓
emit objective_progressed → Journal / Dialog UI 重绘
```

## 4. 示例任务（主场景测试）

| quest_id | 类型 | 委托人 NPC | 目标 | 奖励 |
|---|---|---|---|---|
| `forest_grassland_hunt` | KILL ×2 | 老兵 `veteran_quest_giver` | 杀 forest_monster / archer 各 25 | 100 金 |
| `test_collect_redroot` | COLLECT | 草药师 `herbalist_quest_giver` | 持有 `herb_redroot` ×3 | 30 金 |
| `test_talk_to_merchant` | TALK | 斥候 `scout_quest_giver` | 与 `main_general_merchant` 交谈 | 20 金 |
| `test_enter_east_plaza` | ENTER | 探路者 `pathfinder_quest_giver` | 进入 `main_east_plaza` 触发区 | 25 金 |
| `test_custom_inspect` | CUSTOM | 学者 `scholar_quest_giver` | 调查北侧古石碑（E 交互） | 15 金 |

### 快速验证

1. **采集**：找草药师接任务 → 拾取/采集红根草至 3 个 → J 看进度 → 丢弃 1 个应变为 2/3 → 凑齐后复命。
2. **对话**：找斥候接任务 → 走到西侧商人按 E → 进度 1/1 → 回斥候复命。
3. **区域**：找探路者接任务 → 走到南侧加速踏板附近蓝色触发圈 → 自动完成 → 回复命。
4. **自定义**：找学者接任务 → 北侧紫色「古石碑」按 E → 回复命。

## 5. 扩展指南

### 5.1 新增 COLLECT 任务

复制 `test_collect_redroot.tres`，改 `objective_type = 1`（COLLECT_ITEM）、`target_id` 为 ItemDatabase 中的 `item_id` 即可。

### 5.2 新增 TALK 任务

1. 目标 NPC 配置 `quest_npc_id`（`MerchantNpc` / `CutsceneNpc`）或由 `QuestGiverNpc.npc_id` 自动上报。
2. QuestDef 中 `objective_type = 2`，`target_id` 与 NPC 的 quest id 一致。

### 5.3 新增 ENTER 任务

在场景中放置 `QuestAreaTrigger`（或挂 `quest_area_trigger.gd`），设置 `area_id` 与 QuestDef 的 `target_id` 一致。

### 5.4 新增 CUSTOM 任务

1. QuestDef 中 `objective_type = 4`。
2. 在业务节点调用 `QuestManager.advance_objective(quest_id, objective_id)`，或使用 `QuestCustomTrigger` 预制交互点。

## 6. 已知限制

- `get_relevant_quest_for_npc` 同一 NPC 同时只展示一条最优先任务；测试任务使用不同委托人 NPC 避免冲突。
- CUSTOM 的 `target_id` 仅作文案/设计标识，推进仍依赖 `objective_id`。
- 未实现 QuestTracker 屏幕追踪与 `marker_pos` 导航（见详细设计 §4）。
