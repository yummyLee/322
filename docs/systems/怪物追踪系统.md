# 怪物追踪系统

## 设计目标

- **策略与场景解耦**：追逐逻辑写在 `ChaseBehaviorResource` 子类里，不写 `get_node`、不引用武器/UI。
- **与移动实现解耦**：`ChaseController` 只负责解析目标、读取速度、调用 `evaluate()`、写入 `CharacterBody2D.velocity`。
- **与属性系统松耦合**：移动速度优先取 `CombatantComponent.attributes` 的 `MOVE_SPEED`（词条/装备可改）；未配置时用 `fallback_move_speed`。
- **追逐目标可替换**：通过 `ChaseController.chase_target` 绑定任意 `Node2D`（玩家、NPC、路点）；不绑定时再按组名回退。

## 物理层约定（玩家与怪物互不挤压）

角色移动使用 `CharacterBody2D` 时，若玩家与敌人同层且互相在对方的 `collision_mask` 里，会持续发生物理分离，表现为「顶牛」或抖动。

当前约定（位掩码，与 Godot 检查器「第 N 层」一致）：

| 层位值 | 用途 |
|:--:|:---|
| `1` | 地形 / `StaticBody2D` 等世界碰撞体 |
| `2` | 敌人（含测试木桩等可挨打单位） |
| `4` | 弹丸等（如 `arrow.tscn`） |
| `8` | 玩家角色本体（`player.tscn`） |
| `16` | 玩家受击框 `CombatHurtbox`（敌方近战形状查询用） |

规则简述：

- **玩家**：`collision_layer = 8`，`collision_mask = 1` —— 只与世界碰撞，**不与敌人层互相推挤**。
- **典型怪物**（如 `forest_monster.tscn`）：`collision_layer = 2`，`collision_mask = 1` —— 只与世界碰撞，同样**不推玩家**。
- **武器命中框 / 冲刺撞敌查询**等仍使用各自的 `Area2D` / `PhysicsShapeQueryParameters2D` 的 `collision_mask`（例如只扫敌人层 `2`），与角色本体的移动碰撞无关。

需要让玩家与掉落物等 `Area2D` 重叠时，请将区域的 `collision_mask` 包含玩家所在层（`8`），例如 `world_item.tscn`。

## 追逐目标（攻击/黏附对象）

解析顺序：

1. 若 `ChaseController.chase_target` 已设置且该节点在场景树内，则以其 `global_position` 为追逐点（可为玩家实例、其他 `CharacterBody2D`、标记用 `Node2D` 等）。
2. 否则：`get_tree().get_first_node_in_group(target_group)`（默认组名为 `player`）。

**玩家**仍应在 `_ready` 中 `add_to_group("player")`（项目里已在 `player.gd` 处理），以便未指定 `chase_target` 时行为与原先一致。

在编辑器中：选中怪物的 `ChaseController`，将「Chase Target」拖入场景中的任意 `Node2D` 即可改目标；留空则继续按组解析。

## `ChaseTowardInRangeBehavior` 与攻击距离

- `detection_radius`：与目标距离大于此值时不移动（站立）。
- `attack_range`：与目标距离 **小于等于** 此值时视为已在攻击范围内，**本帧期望速度为 0**，不再持续靠近（避免无意义的位移；具体攻击动画/伤害由怪物脚本另行驱动）。

## 新增一种追逐逻辑

1. 新建脚本 `extends ChaseBehaviorResource`。
2. 实现 `func evaluate(ctx: ChaseContext) -> Vector2`（使用 `ctx.chaser_position`、`ctx.target_position` 或 `ctx.distance_to_target`）。
3. 在怪物的 `ChaseController` 上，将 `behavior` 指到你的 Resource（内联子资源或 `.tres` 均可）。

## 敌人动画帧近战命中（`SpriteFrameMeleeHitbox`）

用于「某段攻击动画只在第 N～M 帧有伤害」：与玩家武器近战相同，命中用 **`PhysicsDirectSpaceState2D.intersect_shape`**，避免移动中的 `Area2D` 漏触发 `body_entered`。

### 为何曾出现「attack 刚播就掉血」

- `AnimatedSprite2D` 在 **`_process`** 里推进 `frame`；若命中逻辑写在 **`_physics_process`**，会在同一引擎帧里**早于**精灵更新去读 `frame`。
- 高 `speed` 或掉帧时，精灵可能在**一次** `_process` 内连跳多帧，从 0 直接落到 `≥hit_frame_start`，与物理阶段错位叠加后，表现为「刚切动画就进命中窗」。
- **对策：** `SpriteFrameMeleeHitbox` 改为 **`_process`**，且节点排在 `AnimatedSprite2D` **之后**，保证读到的是本帧已更新的 `frame`。

### 命中「受击框」还是「整个玩家刚体」？

| 做法 | 优点 | 缺点 |
|------|------|------|
| 形状查询扫玩家 `CharacterBody2D`（层 8） | 少一个节点 | 与移动碰撞同层，体积即全身盒；以后做无敌/部位判定不便 |
| 只扫 `CombatHurtbox`（`Area2D`，层 16） | 与移动分离；可单独调受击体积；易扩展阵营/无敌 | 多挂一个 `Area2D` + 形状 |

**当前工程采用受击框：** 怪物的 `AttackHitArea.collision_mask = 16`，查询时 `collide_with_areas = true`、`collide_with_bodies = false`，打中 `CombatHurtbox` 后把伤害转发给父节点 `on_hit`。

| 路径 | 说明 |
|------|------|
| `scripts/enemies/attack/sprite_frame_melee_hitbox.gd` | `SpriteFrameMeleeHitbox`：`_process` + `animation` / `frame` 窗口 |
| `scripts/core/combat/combat_hurtbox.gd` | `CombatHurtbox`：挂在玩家等角色下，转发 `get_damage_host()` → `on_hit` |

**场景结构（以 `forest_monster.tscn` 为例）：**

```
ForestMonster (CharacterBody2D)
├── AnimatedSprite2D
├── AttackHitArea (Area2D)     ← collision_layer=0, collision_mask=16（只扫受击框层）
│   └── CollisionShape2D
└── SpriteFrameMeleeHitbox (Node)   ← 建议排在 AnimatedSprite2D 之后
```

**检查器参数：**

- `attack_animation`：启用判定的动画名（如 `attack`）。
- `hit_frame_start` / `hit_frame_end`：命中窗口（含端点），与 `AnimatedSprite2D.frame` 一致、**从 0 计数**。例：第五、六帧填 `4` 与 `5`；第三、四帧填 `2` 与 `3`。
- `damage`：对解析后的受击宿主调用 `on_hit(damage)`。
- `query_hit_areas` / `query_hit_bodies`：与 `AttackHitArea` 的 mask 一致；打玩家受击框时为 **areas=开、bodies=关**。
- `hit_forward_offset` / `hit_vertical_offset`：相对怪物的命中区偏移；会按 `AnimatedSprite2D.flip_h` 镜像左右。

**同一挥击内不重复伤害：** 每次从非窗口进入窗口时清空已命中表；窗口内对每个受击宿主实例只结算一次（跨窗口内多帧仍只打一次）。

## AnimationPlayer + 武器位姿（`AnimationDrivenMeleeHit`，通常更简单）

当攻击表现是**单独武器图**或**骨骼/节点**被 `AnimationPlayer` 移动、旋转时，不必在脚本里按 `frame` 或 `offset` 手搓命中框位置：

1. 在会跟着刀/矛动的节点下挂 **`Area2D` + `CollisionShape2D`**（`collision_layer = 0`，`collision_mask = 16` 打玩家受击框，与现工程一致）。
2. 怪物根下挂 **`AnimationDrivenMeleeHit`**，`hit_area_path` 指向上面的 `Area2D`。
3. 在攻击动画里加 **调用方法** 轨道，指向该节点：
   - 出伤起点：`open_hit_window`
   - 出伤结束：`close_hit_window`
4. 与武器同一套动画里 K 帧移动 `WeaponPivot` / `Sprite2D`，命中框作为子节点会一起动；脚本每帧用 `hit_area.global_transform` 做 `intersect_shape`。

| 路径 | 说明 |
|------|------|
| `scripts/enemies/attack/animation_driven_melee_hit.gd` | `AnimationDrivenMeleeHit`：动画轨道开关窗口 + 跟随武器的 `Area2D` |

**和 `SpriteFrameMeleeHitbox` 怎么选：**

| 情况 | 更省事的做法 |
|------|----------------|
| 只有 `AnimatedSprite2D` 逐帧图，没有独立武器节点 | `SpriteFrameMeleeHitbox` + 帧号窗口 |
| 武器是子节点，位姿由 `AnimationPlayer` 驱动 | **`AnimationDrivenMeleeHit` + 调用方法轨道**（一般更直观） |
| 需要与音频/特效帧精确对齐 | 两种都可以在时间轴上对齐；AnimationPlayer 更易和音效轨道同屏编辑 |

**AI 与追逐：`ChaseController`**

- `get_active_target() -> Node2D`：当前追逐目标（与内部解析规则一致）。
- `get_distance_to_target() -> float`：便于在怪物脚本里判断「是否进入 `ChaseTowardInRangeBehavior.attack_range`」并切换攻击动画（见 `forest_monster.gd`）。

**与扇形视野联动：** 巡逻态下由 `./扇形视野系统设计记录.md` 中的 `CharacterAIController` 监听 `VisionConeComponent` 信号，触发后再启用本 `ChaseController` 并设置 `chase_target`。

## ForestMonster 测试怪

- 场景：`scenes/animals/forest_monster.tscn`（`CombatantComponent` + `ChaseController` + `AttackHitArea` + `SpriteFrameMeleeHitbox`）。
- 默认策略：`ChaseTowardInRangeBehavior`（`detection_radius`≈380，`attack_range`≈28）。
- 进入 `attack_range` 时播放 `attack`（`SpriteFrames` 里 **`attack` 不循环**，便于播完后切回 locomotion）；**播放中**玩家离开近战区也不会被打断，整段播完再 idle/walk。由 `SpriteFrameMeleeHitbox` 在配置的帧区间内扫描 `CombatHurtbox`（层 16）并结算伤害（`hit_frame_start=4`、`hit_frame_end=5`）。
- 检查器 **`freeze_movement_during_animations`**：哪些动画在 `is_playing()` 时站桩（默认仅 `attack`）；未出现在列表里的攻击动画播放时仍可被 `ChaseController` 推动。
- 检查器 **`hold_until_finished_animations`**：哪些动画未播完前不因离开近战而打断（默认仅 `attack`）；需与 `SpriteFrames` 里对应动画 `loop=false` 配合。
- 默认在代码中设置 `MOVE_SPEED` 基值（与 `CombatantComponent` 五维默认配套）。
