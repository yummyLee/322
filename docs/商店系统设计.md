# 商店 / 交易界面系统设计文档

> **版本**：1.1（设计 + 首版实现对照）  
> **引擎**：Godot 4.x  
> **项目现状**：已实现 **`MerchantTradeUI`** 拖拽交易、`TradeSettlement` 中立结算、`MerchantNpc` + **`MerchantDefinition`** 进货与定时刷新；可选 **Dialogic** 问候（默认关闭以免挡交易 UI）。

---

## 1. 设计目标

- 与商人对话后打开**交易界面**：左侧玩家背包，右侧商人货架。
- **顶部醒目展示双方「当前资金」**（含本次拖拽产生的**预览结算**，见 §5）。
- **拖拽交互**：商人栏 → 玩家栏 = **购入**；玩家栏 → 商人栏 = **售出**。
- 商人拥有**初始资金**；允许预览中出现**商人资金为负**，用**红色负数**提示「赊账 / 流动性不足」感，**不阻止摆放**。
- 底部 **确认 / 取消**：仅当**玩家与商人预览资金均 ≥ 0** 时可点确认；否则置灰或 `disabled`。
- 点确认后**再弹一层二次确认**（摘要 + 是否执行），防误操作。

非目标（本期可不做或单列 backlog）：世界物价波动、讨价还价小游戏、多商人联播库存、联机同步。

## 2. 参考其他游戏的机制（提炼可借鉴点）

| 参考来源 | 可取机制 | 与本设计的对应 |
|---------|---------|----------------|
| **《星露谷物语》** | 商店左右分栏、钱包与出售价即时反馈 | 左右分栏 + 顶部资金随「暂存区」变化 |
| **《我的世界》村民交易** | 买方支付固定货币、库存与职业绑定 | 商人初始资金 + 货架配置；确认时原子结算 |
| **《神界：原罪》类物换物** | 双方物品 + 金币增减同一屏消化 | 双侧格子 + 双向拖拽；用预览金币统一表达 |
| **《泰拉瑞亚》等点击商店** | 一键买卖简单 | 本期以拖拽为主，可后续加「右键快速买卖」快捷方式 |
| **《Kenshi》等模拟经营** | 商人现金不够仍能成交（负债或赊账） | **允许商人预览为负**（红色），用确认门槛约束「正式成交」 |

**设计结论**：采用「**暂存式交易台**」——界面上的摆放不代表立刻改存档，只有**确认**后才一次性写入背包与金币；取消则完全回滚 UI 状态。这样既满足「可拖到负钱预览」，又不会误伤存档。

## 3. 核心概念

### 3.1 暂存交易（Staging）

- **基础状态**：打开界面时，从 `Player.inventory` / `Player.gold` 与商人实例的 `stock + gold` **各拷贝一份**到 UI 层用的「会话数据」。
- **拖拽**只修改会话数据中的两侧格子与**预览金币**，不写真实存档。
- **确认**：在校验通过后，将会话数据**原子提交**回玩家与商人。
- **取消**：丢弃会话数据，关闭界面。

### 3.2 价格模型（建议）

现有 `ItemData.value_gold` 可作为**基准价**，避免每个商人重复填价：

- **玩家买入价** = `ceil(value_gold * buy_multiplier)`（商人-specific，默认例如 `1.0` 或 `1.2`）。
- **玩家卖出价** = `floor(value_gold * sell_multiplier)`（默认例如 `0.5`，经典「卖店半价」）。

可选扩展：`ItemData` 或目录 JSON 增加 `flags`（如 `不可出售`、`任务物品`），商人侧 `黑名单/白名单`。

### 3.3 商人数据（资源 + 运行时）

| 层级 | 内容 |
|------|------|
| **配置** | **`MerchantDefinition`**（`scripts/core/merchants/merchant_definition.gd`）：`merchant_id`、`merchant_display_name`、`stock_entries`、`starting_gold`、`buy_multiplier`、`sell_multiplier`、`stock_refresh_interval_sec`、`reset_gold_on_stock_refresh`。 |
| **进货模板项** | **`MerchantStockEntry`**：`item_id`、`quantity_min` / `quantity_max`（每次刷新随机数量）。 |
| **运行时** | **`MerchantNpc`**（`scripts/world/merchant_npc.gd`）：`merchant_inventory`、`merchant_gold`；槽位数与玩家一致，沿用 **`Inventory.SLOT_COUNT`**。 |

交互与集成：

- **`trade_ui_path`**：`NodePath` 指向场景中的 **`MerchantTradeUI`**（如 `Main` 下 `../MerchantTradeUI`）。
- **`dialogic_timeline`**：对话时间轴键名或 `res://...dtl`；**默认为空**，仅打开交易 UI；若填写则会叠加 **`Dialogic.start(...)`**（可能与面板叠层，按需二选一）。
- **信号**：`trade_requested(merchant)`，可供任务或其它系统监听。
- **输入**：交易 UI 打开时，`MerchantNpc` 不再响应 **E**（与经验商人挡交互一致）。

### 3.3.1 货架刷新与「玩家寄卖」标记

- **定时刷新**：`stock_refresh_interval_sec > 0` 时挂 **`Timer`**，到时先 **`_purge_unrepurchased_player_sales()`**（清空仍标记为玩家寄卖的格子），再按模板 **`_restock_from_definition()`**；若 `reset_gold_on_stock_refresh` 为 true，刷新前将商人金币重置为 `starting_gold`。
- **寄卖 API**：`mark_slot_as_player_sale`、`clear_player_sale_mark`、`prune_invalid_player_sale_marks`、`copy_player_sale_slot_marks_into`、`replace_player_sale_marks_from_session`（交易确认后由 UI 写入会话标记）。
- **示例资源 / 场景**：`resources/merchants/general_vendor.tres`；`scenes/main.tscn` 中的 **`MerchantNpc`** + **`MerchantTradeUI`**。

### 3.4 中立结算模块：`TradeSettlement`

路径：**`scripts/core/items/trade_settlement.gd`**（**`class_name TradeSettlement`**）

与具体 NPC、玩家脚本、UI **解耦**，只操作 **`Inventory`** 与金币数值。

| API | 用途 |
|-----|------|
| **`duplicate_inventory` / `copy_inventory_into`** | 会话 staging、格子级拷贝（含耐久）。 |
| **`commit_two_party_session`** | 将「会话」两侧背包覆盖写回真实 **`player_inventory`** 与 **`counterparty_inventory`**，并返回 **`Result`**（`player_gold_after`、`counterparty_gold_after`、`ok`、`fail_reason`）。写入对方失败时用备份回滚玩家侧拷贝。**当前 `MerchantTradeUI` 确认成交走此路径**（支持耐久与任意格子状态）。 |
| **`settle_line_items`** | 传入 **`PurchaseLine`** / **`SaleLine`** 数组，在模拟背包上验证后一次性扣货、发货并结算金币；**`LineOptions`** 控制双方成交后金币是否允许为负。**限制**：行项目中含 **`max_durability > 0`** 的物品会直接失败（需改用快照 **`commit_two_party_session`**）。 |
| **`PurchaseLine`** | `item`、`quantity`、`unit_price_player_pays`、可选 `vendor_source_slot_index`（`-1` 则按物品 id 自动扣堆叠，仅无耐久）。 |
| **`SaleLine`** | `item`、`quantity`、`unit_price_player_receives`、可选 `player_source_slot_index`。 |

流程分工：**UI / NPC** 负责预览、倍率、寄卖标记；**提交库存与金币数值**统一经由 **`TradeSettlement`**（或直接调用上述 API 的其它系统，如任务商店）。

## 4. 界面布局（线框说明）

```
┌─────────────────────────────────────────────────────────────┐
│  [玩家资金] 大额数字 + 货币图标     │  [商人资金] 同上        │
│  预览变化可用 +/- 次级色或动画提示   │  负数为红色              │
├──────────────────────┬──────────────────────────────────────┤
│                      │                                      │
│   玩家背包格子网格    │        商人货架格子网格               │
│   （拖拽目标/源）     │        （拖拽目标/源）                │
│                      │                                      │
├──────────────────────┴──────────────────────────────────────┤
│            [ 确认 ]          [ 取消 ]                          │
│   确认：双方预览金币≥0 可用；否则 disabled + Tooltip 说明       │
└─────────────────────────────────────────────────────────────┘
```

**醒目资金条建议**：

- 字体显著大于格子内文字；可加浅色底条或描边。
- **负数**：红色文字 + 可选轻微脉冲/图标（不要过度遮挡）。

## 5. 拖拽与结算预览

### 5.1 单向操作的语义

- 从**商人格**拖到**玩家空位或可合并格**：视为**欲购入**  
  - 玩家预览金币 `-= 买入价 * 数量`（按实际移动堆叠数量算）。
  - 商人预览金币 `+= 同上`（物品款流入商人）。
- 从**玩家格**拖到**商人格**：视为**欲售出**  
  - 玩家预览金币 `+= 卖出价 * 数量`。
  - 商人预览金币 `-= 同上`。

同容器内排序（仅玩家侧或仅商人侧）若需要：按「换位」处理，**不改变双方金币**。

### 5.2 堆叠与拆分

- **整格拖动**：默认移动整堆（不超过 `max_stack`）。
- **Shift + 拖** 或 **中键拆分**： industry 常见做法；首版可只做整格，拆分列入二期。
- **合并**：同 `item.id` 且耐久规则一致时合并；**耐用品**需约定：仅满耐久可合并，或禁止跨耐久合并（与现有 `Inventory.move_item` 行为对齐）。

### 5.3 非法目标

- 目标格已满且无法合并 → **拒绝放置**并回弹动画或 Toast。
- 任务物品不可卖 → 禁止拖到商人侧或拖入时提示。

## 6. 确认 / 取消与二次弹框

### 6.1 确认按钮启用条件

同时满足：

1. `preview_player_gold >= 0`
2. `preview_merchant_gold >= 0`
3. （可选）双方各自背包容量合法、无「悬空」的中间状态——若全程格子合法则已隐含。

不满足时：`disabled = true`，Tooltip 示例：「资金不足：玩家或商人不能有负债。」

> **与需求的对应**：允许界面里把商人拖到负数（红色显示），但**不允许在这种状态下成交**；玩家负数同理。

### 6.2 第一次点「确认」

弹出 **AcceptDialog**（或后续替换为自定义 Panel）：

- **目标**：摘要 `购入列表`、`售出列表`、**玩家金币变化**、**商人金币变化**。
- **当前**：仅通用确认文案；条目级摘要仍为 backlog（见 §10）。
- 按钮：**「确定」** / 关闭即取消。
- 仅当仍满足 §6.1 时「确定交易」可用（防止弹窗打开后底层被改——若架构上不可能并发可省略）。

### 6.3 二次确认后（当前实现）

1. 调用 **`TradeSettlement.commit_two_party_session`**：会话背包 → `Player.inventory` / `MerchantNpc.merchant_inventory`，会话金币 → 返回值写入 **`Player.gold`**、**`merchant_gold`**。
2. **`MerchantNpc.replace_player_sale_marks_from_session`**：同步本轮 UI 中记录的寄卖格子标记。
3. 关闭 **`MerchantTradeUI`**。

**尚未实现**：全局信号 **`shop_transaction_completed`**、成交摘要写入二次弹框正文（当前仅为通用确认句）。

---

### 6.4 取消

- 直接关闭，不写回商人（商人会话拷贝丢弃）。

## 7. 与 Dialogic / 场景的集成流程（已实现）

1. 玩家在 **`MerchantNpc`** 感应范围内按 **E** → **`open_for_merchant(self)`**（**`MerchantTradeUI`**，由 **`trade_ui_path`** 解析）。
2. 若配置了 **`dialogic_timeline`** 且非空 → **`Dialogic.autoload`** 上 **`start(timeline)`**（已有对话进行时不再重复打开）。
3. **`MerchantTradeUI`** 使用 **`UILayerManager.bring_to_front`**；**CanvasLayer** 层级与 **`ExperiencePurchaseUI`** 类似单独抬高。
4. 关闭交易 UI 后无强制 Dialogic 分支（可按需在商人资源上继续播时间轴或留空）。

主场景引用：**`scenes/main.tscn`** → **`MerchantNpc`** + **`MerchantTradeUI`**；杂货模板 **`resources/merchants/general_vendor.tres`**。

## 8. 边界情况清单

| 情况 | 处理 |
|------|------|
| 玩家背包满，购入无空位 | 禁止放入或仅允许可合并格 |
| 商人货架满，售出无空位 | 同上 |
| 买入/卖出价为 0 | 允许，预览金币不变 |
| 商人初始 gold = 0 | 仍可向其**出售**（商人 preview 变负）直到玩家摆到合法再确认 |
| 关闭游戏时界面未确认 | 不提交，无副作用 |
| 多商人并行 | 单例 UI，一次只绑定一个 `merchant_id` |

## 9. 技术实现要点（Godot，与代码对齐）

| 模块 | 路径 | 说明 |
|------|------|------|
| 交易 UI | `scripts/ui/merchant_trade_ui.gd`，场景 `scenes/ui/merchant_trade_ui.tscn` | 双栏 **`GridContainer`**；**`TradeSlotUI`** 格子；会话 **`Inventory`** + 预览金币；商人侧**不允许**同栏内换位整理，玩家侧允许 **`move_item`**。 |
| 交易格子 | `scripts/ui/trade_slot_ui.gd` | 拖拽 payload：`trade` / `side` / `slot`；悬停 tooltip 由 **`MerchantTradeUI.show_item_tooltip`** 显示购入/售出单价。 |
| 结算 | `scripts/core/items/trade_settlement.gd` | **`commit_two_party_session`**（UI 提交）、**`settle_line_items`**（脚本化购销列表）。 |
| 商人 NPC | `scripts/world/merchant_npc.gd`，`scenes/world/merchant_npc.tscn` | **`InteractableObject`**；刷新 **`Timer`**；寄卖字典 **`_player_sale_slots`**。 |
| 商人配置 | `scripts/core/merchants/merchant_definition.gd`、`merchant_stock_entry.gd` | `.tres` 资源配置。 |

其它：

- **性能**：当前实现为变更后刷新两侧全部格子；后续可改为按槽位增量刷新。
- **暂停**：未全局暂停游戏树；仅挡 **`MerchantNpc`** 重复 **E**。
- **无障碍/手柄**：仍为 backlog（§11）。
