# 开发路线图（openworldtest）

> **引擎**：Godot 4.x  
> **用途**：在已有原型之上，按阶段补齐 RPG 常见的「管家系统」与体验闭环；条目可随版本裁剪或重排。  
> **相关文档**：[商店 / 交易系统设计](商店系统设计.md) · [核心循环补全详细设计](核心循环补全详细设计.md)（本路线图的实现级配套）

---

## 1. 现状基线（便于对照）

下列能力已在工程中出现或可引用（不完全枚举）：

| 领域 | 已有内容 |
|------|-----------|
| 角色 / 进度 | `Player`、等级经验、`PlayerRuntimeState` 跨场景快照 |
| 物品 | `Inventory`、`Equipment`、`ItemDatabase`（目录 JSON）、耐久 |
| 战斗 / 技能 | 武器与投射物、`SpellSystem`、Buff 相关脚本 |
| 任务 | `QuestManager`、`QuestDef`、任务 NPC 与对话 UI |
| 叙事 | `Dialogic`、过场 `CutsceneManager` |
| 世界 | 采集点、地面拾取物、`InteractableObject` |
| 交易 | `MerchantNpc`、`MerchantDefinition`、`MerchantTradeUI`、`TradeSettlement` |
| UI 基础 | `InventoryUI`、`UILayerManager`、调试菜单等 |

**相对典型的成品 RPG 仍常见的缺口**：完整磁盘存档、统一游戏设置与键位、地图/目标追踪、结构化掉落、死亡与重生规则、本地化与音频分层、性能与测试管线等（详见下文阶段）。

---

## 2. 分期原则

1. **先闭环**：能「玩得下去、存得住、找得到路」再堆内容深度。  
2. **数据驱动优先**：任务、物品、商店、掉落尽量走资源/表，减少硬编码分叉。  
3. **与现有 Autoload 对齐**：新系统优先挂接 `QuestManager`、`PlayerRuntimeState`、`TradeSettlement` 等，避免平行造轮子。  
4. **每阶段有可演示里程碑**：便于迭代与取舍。

---

## 3. 阶段概览

| 阶段 | 主题 | 目标一句话 |
|------|------|------------|
| **P0** | 地基 | 存档可读档、设置与输入可用 |
| **P1** | 游玩清晰度 | 目标可见、失败可恢复、状态可读 |
| **P2** | 世界与经济深度 | 掉落与旗帜驱动成长与探索回报 |
| **P3** | 规模化与打磨 | 本地化、音频、性能、自动化校验 |
| **Backlog** | 可选加分项 | 按题材取舍 |

---

## 4. P0 — 地基（强烈建议优先）

| ID | 内容 | 说明 |
|----|------|------|
| P0-1 | **完整存档 / 读档** | 多槽位；持久化玩家背包、装备、金币、等级、`QuestManager` 状态、商人库存与金币（若需）、关键世界旗帜；定义存档版本号与升级/作废策略。 |
| P0-2 | **统一游戏设置** | 主菜单或暂停内：主音量、音乐/音效分轨、全屏与分辨率、语言（预留）。 |
| P0-3 | **键位绑定** | 交互、背包、地图（占位）、技能栏等可重绑定；写入设置并跨会话保存。 |
| P0-4 | **主菜单流程** | 新游戏 / 继续 / 设置 / 退出；与 `run/main_scene` 衔接清晰。 |

**里程碑**：任意时长游玩后可存档退出，再进入进度一致。

---

## 5. P1 — 游玩清晰度与对抗闭环

| ID | 内容 | 说明 |
|----|------|------|
| P1-1 | **任务目标追踪 UI** | 当前任务目标列表、可选追踪点（最少：文本 + 方向/距离占位）。 |
| P1-2 | **地图或小地图** | 从极简示意图起步；与任务标记、传送点（若以后有）兼容。 |
| P1-3 | **死亡 / 战败流程** | 重生点、读档提示或轻度惩罚；与战斗数值挂钩，避免软锁。 |
| P1-4 | **战斗状态可读性** | Buff/Debuff 图标与剩余时间或层数；伤害飘字已有则可统一风格。 |
| P1-5 | **加载与过渡** | 场景切换淡入淡出或异步加载提示，减少黑屏突兀感。 |

**里程碑**：新人不看代码也能在「接任务 → 战斗失败 → 重来 → 交任务」链路里自助完成。

---

## 6. P2 — 世界运转与经济深度

| ID | 内容 | 说明 |
|----|------|------|
| P2-1 | **世界状态 / 剧情旗帜** | 集中管理布尔或枚举标志（门、NPC 阶段、商店解锁）；供任务与对话查询。 |
| P2-2 | **掉落表（Loot）** | 敌人/宝箱权重表；与 `ItemDatabase` id 对齐；可先做 CSV/Resource。 |
| P2-3 | **合成 / 强化 / 修理（可选）** | 与耐久、`value_gold`、商人收购价形成闭环；可分二期只做修理站。 |
| P2-4 | **脚本化交易扩展** | 任务奖励商店、一次性商人：复用 `TradeSettlement.settle_line_items`。 |
| P2-5 | **昼夜或日程（可选）** | 若要做城镇节奏：与商人刷新、NPC 出现时段挂钩（可与现有 `stock_refresh_interval_sec` 分层）。 |

**里程碑**：探索与战斗有稳定收益曲线；内容可加在数据层而非每次改脚本。

---

## 7. P3 — 规模化、本地化与工程化

| ID | 内容 | 说明 |
|----|------|------|
| P3-1 | **本地化管线** | 提取 UI / `Dialogic` 字符串；统一 PO 或 Godot 翻译资源。 |
| P3-2 | **音频分层** | 探索 / 战斗 / 城镇音乐切换；音效池或并发上限防卡顿。 |
| P3-3 | **性能清单** | 开放世界相关：视野裁剪、实例池、Profiling 门槛（Draw Calls、物理）。 |
| P3-4 | **自动化测试** | 对 `TradeSettlement`、任务状态迁移等关键逻辑做单元或场景测试。 |
| P3-5 | **内容校验工具** | 扫描物品 id、任务引用、对话占位符是否断裂（CLI 或小编辑器插件）。 |

**里程碑**：新增一批物品/任务不靠「人肉扫坑」也能快速发现配置错误。

---

## 8. Backlog — 按题材取舍

- 同伴 / 小队与编队 AI  
- 成就与统计面板  
- 图鉴（怪物 / 物品）  
- 难度档位或动态难度  
- 随机事件 / 遭遇战规则  
- 建造或领地（若与开放世界方向一致）  
- 联机（通常单独立项）

---

## 9. 建议的近期顺序（默认单机剧情向开放世界）

1. **P0 全套**（存档 + 设置 + 键位 + 主菜单）  
2. **P1-1 → P1-3**（追踪、简易地图、死亡流程）  
3. **P2-1 → P2-2**（世界旗帜 + 掉落表）  
4. 视内容体量启动 **P3-4（测试）/ P3-5（校验工具）** 减轻回归成本  

商店与交易详设仍以 **[商店系统设计.md](商店系统设计.md)** 为准；本路线图不重复展开 UI 细节。
